# 跨宿主对话操作指南 —— 让 dsh 的会话在 femo 戏里接你的话

> 适用：zcode 窗口当导演，用 femo 跑一场小戏，让 dsh-3081 侧挂了 soul 的会话接话。
> 全链已于 2026-09-25 真演出跑通（job 2584《跨宿主三句话》，三拍台词全入账、finished 零报错）。
> 本文是操作契约：跟着做能成功；出问题按「排查工具箱」定位。

## 一句话流程

写剧本（导演用 source:main，dsh 角色用 soul）→ 挂载 → 干跑 → femo_run 开演 → 补一笔本场选角账 → 架哨兵等信 → 唤醒即演（纯文本回答就是交卷，插件自动收卷）→ 收尾前再架哨兵 → 循环到终局信「✅ FEMO 已跑完」。dsh 角色的信不用管（收件口自动拉活本尊出演）。

## 零、前置条件（开工前一眼扫）

1. 三个端口活着：3081（dsh）、8790（hub）、还有你自己的 zcode MCP。用 `netstat -ano | grep LISTEN` 看。
2. dsh 侧桥活着：进程表里有 `python.EXE ... femo_bridge.py --host dsh-3081`。死了会自愈（C1 看门狗约十几秒重生），重生即加载最新代码。
3. femo 插件在 3081 上是 **junction 直连开发仓**（`dsh-home/profiles/web/node_modules/femo-plugin` → `hostAdapter/dshAdapter`），所以 `node build.mjs` 构建=部署，重启 3081 后生效。
4. hub 选角账是唯一权威：`GET http://127.0.0.1:8790/sessions/cast-preferences`。**dsh 界面上的绑定显示可能骗你（它读自己的会话档案），一切以这本账为准。**

## 一、绑定（把 soul 挂到 dsh 会话上）

走 hub 端点（和 dsh 界面绑定按钮同一条路）：

```
绑定：POST http://127.0.0.1:8790/sessions/cast-preference
     {"host":"dsh-3081","sid":"<dsh会话id>","soul":"<soul_id>"}
解绑：同上，soul 传 null
```

规则与坑：
- **提名制（2026-09-26）**：一个会话一格，提新角色直接顶替（免先解绑）；同一角色多个会话可各提各的，谁当选=最后一次指派，自下一场开演定格起生效，在跑的戏不受影响。没有「已被占用」报错——想让谁演，就对谁再提一次。
- dsh 会话 id 从名册抄：`user_data/projection/roster.json` 的 `hosts["dsh-3081"]`，按 since_t 排最新的、或按会话标题认。
- 绑完必须 `GET /sessions/cast-preferences` 验账（ bindings 里 soul → {sid, host:"dsh-3081"} 且唯一）。
- **别在界面上点完绑定就以为稳了**：直写 hub 后 dsh 界面显示可能不跟（读的是它自己的档案），以账本为准。

## 二、写剧本（存 user_data/projects/）

骨架照抄（三拍对话最小形）：

```
meta:
  name = 跨宿主三句话
  session = new
actors:
  ai @ZCode = source:main            ← 你（导演）亲自下场
  ai @小猫咪 = soul:littlecat        ← dsh 侧会话出演（soul 换成你绑的那个）
action 开场 @ai(@ZCode):
  prompt: "…"
  scope: [@小猫咪]
action 回应 @ai(@小猫咪):
  prompt: "…"
  scope: [@ZCode]
action 道别 @ai(@ZCode):
  prompt: "…"
  scope: [@小猫咪]
mainflow:
  [START] -> 开场 -> 回应 -> 道别 -> [END]
```

- 改过剧本必须重新 femo_mount 再跑，否则跑的是旧版。
- 干跑（femo_debug）必跑且必须全绿（结局 completed、边覆盖 100%）再开演。

## 三、开演与导演自己的拍怎么交

1. `femo_run fresh_start`，记下 job_id。
2. **立刻补一笔本场选角账**（当前 hub 进程是旧代码时自动誊写不生效，手动补；hub 进程重生过之后这步可省）：

   ```
   POST http://127.0.0.1:8790/cast   {"job_id":<job_id>,"subkind":"snapshot"}
   验账：GET http://127.0.0.1:8790/cast?job=<job_id>   ← 必须能看到你的 soul → dsh-3081
   ```

3. **架 femo-possess 守夜等自己的下一拍信**（Bash `run_in_background`；演出中唯一要跑的命令；2026-09-28 起附身+守夜一体——不带 `--session_id` 就是「附身自己」，程序自动自证本窗会话号（CLAIM 暗号→exec 目录搜回）并落提名账，然后进入守夜）：

   ```
   FEMO_ROOT="D:/myFiles/dsh/femo-plugin" node "D:/myFiles/dsh/femo-plugin/hostAdapter/zcodeAdapter/runtime/femo-possess.mjs" --action possess --soul_id main --timeout-min 30
   ```

   守夜只读信柜不消费信，见到寄给本席的 pending 信约 1 秒内退出——宿主原生唤醒你（回合真闭合、页面真停、插话正常对话零排队）；30 分钟无信超时退出，醒来重架即可。替别的会话派角/解附身走同程序带 `--session_id`（跨宿主再加 `--host`，一次性落账即退）。不要用 Stop 钩子干等（只在收尾时触发，时序差），也不要当轮内 sleep 硬等（占住整轮、页面挂运行标记、插话排队）。
4. **被唤醒 = 轮到你：先架守夜，再把台词作为本回合最后一条消息正常回答——回答就是交卷**。唤醒通知里已带齐上下文、节点提示、showprompt；宿主只把本回合最后一条消息交给收卷器，所以台词必须最后说（纯文本，不调任何 femo 工具、不敲任何命令、不读任何文件），说完真闭合（回到第 3 步等下一拍）。
5. dsh 角色的拍**不用管**：信会投到 dsh-3081，收件口查本场账→拉活座位会话→主会话本尊出演→回信自动寄回。zcode 侧继续第 3-4 步循环。
6. 终局：导演交完最后一场后，架 `--soul_id main` 守夜等终局信「✅ FEMO 已跑完」——job 档案 state=finished 即收工。

## 四、45 秒协议与排查工具箱（全是只读，不碰演出）

45 秒没回信，按顺序查：

1. **台账**：`python femo2host/femoToolcall/chronica.py`（最新场）。台词进没进、是不是空台词。
2. **邮箱**：mailbox.json 里 dsh 角色那封信的状态——
   - `pending`：没人取 → dsh 侧桥死了，杀掉等自愈；
   - `delivered`（sent_via=system_push）：已被 dsh 收件口取走 → 看第 3 步；
   - `consumed`：引擎吃了 → 信已经闭环，是台账回填慢，再等等。
3. **dsh 侧活控制台**：`dsh-home/meow-3081-hubfeed.out.log`，grep 关键词：
   - `adopted foreign job` → 收编成功，本尊在跑，再等等；
   - `adopt failed: …` → 按原因处理（查无座位=没补账；绑在别家=绑定账错了；拉活失败=会话拉不活）；
   - `brief for unknown job` → 3081 跑的还是旧构建 → 重新 build + 重启 3081；
   - `seat 拉活 … => 失败` → 座位会话拉不活（官方 resume 不可用），查 3081 启动日志。
4. **投影窗数据**：`GET http://127.0.0.1:8790/view?job=<job号>`（注意用 **job 号**，不是台账场次号，两者不同）。只有 play_start/play_end 没有中间行 = 演员信没被演。
5. **桥流水**：`user_data/debug-mailbox-poll.log` 里 grep job 号——回信的 `drain … target=zcode` + `handin delivered=True` = 引擎收讫；`target=dsh-3081` + `job_not_active` = 回信寄错了方向（旧版 bug，已修，出现=构建没生效）。

## 五、当前版本的坑（每个都真踩过）

1. **hub 进程旧代码**：自动誊写选角账的代码活在 hub 进程里，幸存 hub 没重生就不生效 → 每场开演后手动补 snapshot（第三节第 2 步）。
2. **引擎 3600 秒空放**：演员一直不回，引擎等满 3600 秒会记**空台词**放行并继续走完、show 记 finished 无 error。台账时间戳每拍正好 +3600s 就是它。所以别干等，45 秒没动静就排查。
3. **pause/resume 是冻结不是重派**：引擎活着时暂停/续跑不会重发没答完的拍；重新派拍只发生在桥死后冷恢复（这也是为什么别用续跑来「催」演员）。
4. **两本号别混**：job 号（jobs/runs/、投影 /view、/cast、/owner 都用它）≠ 台账场次号（chronica 用它）。
5. **wait_key 序号是全场递增**（[开场]=1、[回应]=2、[道别]=3），不是重试计数，别被 `_2` 骗了以为重试过。
6. **别手动搬信、别手改邮箱**：地址/投递问题一律修产信端，手动搬只会把账搅乱。
7. **绑定操作要走用户可见的路径**：直写 hub 前先说一声要动什么；解绑→再绑两步做完当场验账；dsh 界面显示不同步时以账本为准并提醒用户刷新。
8. **多 hub 并存**：netstat 出现多个 87xx 监听 = 桥重启自愈时各自自起了 hub（选角账内存副本会分叉）。以「数据根 hub.json 指向的那座」为准；乱得厉害就杀掉多余桥让它们重生归拢（hub 唯一化二期前的已知债）。
9. **zcode 侧 femo_possess 已可用（2026-09-27 直达式）**：只给 soul_id 即可——提交钩子在每次用户发言时把本窗口真实会话号登记在案，possess 取「最近提交发言的会话」当场落提名，唯一讲究是附身前后别在别的 femo 窗口按回车说话。替别家宿主的会话派角：带 host + session_id。绑完仍以 cast-preferences 账验账为准。（号源全失时工具自动退 90 秒认领牌兜底，由钩子补全提名。）
10. **3081 重启后所有会话窗口全关**：跨宿主座位会话由收件口自动拉活（ensureSessionLive），不用人点开；若拉活失败会响亮报错，按日志处理。
11. **双监听残影**：重启 3081 的退场瞬间 tailscale 侧可能出现第二个监听 pid，是残影非撞车，看进程 start time 判断。

## 六、成功长什么样

- 台账三拍台词全有内容；

- 投影窗 `GET /view?job=<job_id>` 有 play_start、各节 section、play_end 行。
