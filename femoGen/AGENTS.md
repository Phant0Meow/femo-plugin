## 一、画布是什么，不是什么

femoGen 是 femo 系统自带的友善工具，负责自动生成 femo 代码，可以 debug，也可以预览运行。在架构上，很多时候可以把画布看作一个宿主——它有很多信息可以从公共层接收，这样方便一些。

画布的本职是两件事：**拖拽生成剧本**，以及一个**干跑调试窗**——跑一遍的流水（节点进出、变量怎么变、哪里重试告警）实时滚在面板里，末尾给终报。写完剧本先自检再开演。

画布的两条边界要说死：

- **画布是编辑器，不是输入席**。人类输入入口在宿主侧（见 hostAdapter 守则），画布上的输入浮层只是演出途中（且看的是自己那场戏）的应急通道，不是常驻聊天面；观演别家的场时只有等待状态显示、没有输入席。
- **画布是纯显示者，不是指挥家——显示直连引擎，指挥守控制面（2026-10-05 画布直连改口径）**。开跑之后的画布只看直播画状态：节点呼吸灯、断点亮点、人类等待，全是引擎事件的回声——而且是**直连常驻引擎**的回声（观察者身份 `?observer=femogen`，全场合法观看；细则见 docs/ActiveRoadmaps/画布直连引擎施工清单.md）。控制面边界不破：运行=宿主回调（守卫/record/挂载是宿主职责）；停止/继续=引擎命令直发（投影中心同级）；人类输入浮层（自己的场）=引擎命令直发。画布不报门铃心跳、不代拉引擎——开着画布不构成「这场戏该继续演」的理由。

## 二、三种形态与接入纪律

画布一套代码，有三种被打开的方式：

1. **插件模式（dsh）**：宿主只准 import 公共层门面 femo_gen_api.jsx（画布对宿主的唯一公开 API，与引擎门面同一取向，住在 femo2host/）——dsh 把它打进聊天窗构建。**引擎脸（2026-10-05 起）画布直连引擎**：开机向同源 `GET /femo-plugin/engine-base` 现问引擎地址（dsh 的薄插座在 routes/engine-gateway.ts），事件流/校准/观演直发引擎；宿主脸仍走宿主回调——运行（凭证/班底/守卫）、record、文件面、干跑。宿主还剩一件事：远程/webview 被拦时当透明转发管子（engine-relay，只转发不改写）。
2. **托管模式（zcode、web 本地服务）**：消费 vite 构建成品 dist（构建唯一出处是 femoGen 目录）。zcode 网关静态托管；web 本地服务另以一层薄伺候补齐文件面（见 §十一）+ 同款 engine-base/engine-relay 两插座（web 的 engine-base 按请求 Host 头裁决可达性：回环给直连地址、非回环给转发路——引擎绑 127.0.0.1 是安全姿态，手机走 tailscale 时浏览器够不着引擎）。
3. **独立模式（vite 开发服 / 公网部署）**：画布诞生时的原形态。引擎脸照常工作（伺候方有 engine-base 就直连，没有则显「引擎离线」等地址）；仓库里的介绍页与语法文档页也随这套构建一起出。

生效链：改完画布，dsh 侧重构建聊天窗；zcode 侧跑 developer/scripts/sync-zcode-dist.ps1；web 侧先在 femoGen 目录跑构建、再刷新即生效（服务逐请求现读 dist，不用重启）。三份同步纪律见根 AGENTS §八。

还有一条**反向契约**：画布前端直调的宿主路由族（/femo-plugin/* 与 SSE 事件流）**归宿主所有**，不在画布门面的契约里——那是宿主暴露给画布的 API 面。接新宿主、盘点老宿主，先读 docs/Specs/宿主接入清单.md。

画布的引擎直连客户端收口在公共层（femoGenConnector/engine-client.mjs，刀1：命令/订阅/健康探针/清单档案读取/跟随策略 pickJob/帧开壳，浏览器与 Node 通用）——直连纪律只有一份，宿主各自只做地址发现与转发两个薄插座。旧宿主转播通道（femoGenConnector/sse-core.mjs）仍在役但消费方只剩聊天窗逐字流等宿主自有面，画布不再吃转播。

## 三、一份剧本的三份形态与统一语义

- femogen 里一份剧本有三份形态：**record（宿主会话账本，唯一权威）**、画布图、编辑器文本。后两份是工作副本，改任何一处都可能造成三端不统一。
- **画布绝不自动回写文本**。这是 2026-08-22 的大重构裁决：此前任何画布变化都会过几秒全量重生成并覆盖 record，「打开看一眼就污染原文」的元凶就是它。现在一切统一走两个显式定稿按钮——文本生图、图生文本；定稿那一刻才写回 record，顺手建立新的结构基线。
- 「图被修改」的判定是结构签名：增删节点连线、改标签、内联编辑动作说明都算修改；拖动挪位置不算（坐标是排版，不是内容）。
- **守卫时时刻刻存在，永远在 run 按下之后检查**（作者原话：「守卫时时刻刻存在，它永远在run按钮按下之后检查。」）——AI 工具调用也不例外。
- **mount ≈ 人类导入**：两者都是明确要求「我就要这一版」的语义，强行让三端统一于这一版、清掉脏标记。（作者原话：「AI mount的行为类似于femogen里人类导入femo。mount和导入是明确要求“我就要这一版”的语义，所以就是会让多端统一于这一版的。」）
- 所以 mount 之后可以直接跑（守卫必然放行）——除非 mount 之后又有别处改了剧本，三端再度不统一，此时手动按钮与 femo-run 都会拦下来问。
- 「到底跑哪个」的裁决原则是**问权威，不猜本地**：页面不可能知道剧本在没在跑（直播断了本地 running 就是残影），本地状态只当作「该去问」的触发条件，引擎档案说了算；问失败则交给宿主的守卫兜底。

## 四、图与文本的对偶——往返无损是底线

画布的心脏是一对互逆的纯函数：解析器把文本变成图，生成器把图变回文本；图转换居中搭桥。围绕这一对函数，有两条铁律：

- **往返必须无损**。作者写在剧本里的东西，经过「文→图→文」一圈不许丢、不许改：文件头的架构说明注释要在解析时抢救出来、生成时原样回写（哪怕一个节点都没摆）；节点排版坐标以草图注释块的形式存进文本（引擎忽略、画布还原）；作者没写的东西不许编造——比如没有灵魂设定的角色保持裸写法，绝不伪造一个数字灵魂。
- **「未声明」与「显式选择」是两种语义，不许归一**。最典型的执行者工具三态：不写=宿主默认全开、写 false=明确禁用、写清单=白名单——历史上归一化曾把「禁用」悄悄吞成「未声明」，语义静默丢失。这是根 AGENTS「少兜底」红线在画布的具体化：兜底不是善意，是篡改。

生成端还有一件「善意的兜」要分清：**自动变量规划**。生成剧本时，动作里用到而未声明的变量会自动补进声明区，跨作用域的变量升到剧本级——这是因为引擎的帧栈里模块局部会遮蔽全局，跨作用域变量留在模块里出模块即丢。注意方向：这是生成端的善意，替作者把「先声明后赋值」补齐；运行端遇到错误依然必须报错，绝不宽容（根 AGENTS 引擎红线）。

另有一条解析期的语义裁决：**图模型不建合流节点**。文本里的 join 语法在解析期摊平成普通边；而普通的多线汇入绝不自动升级成「等全部到齐」——历史上互斥分支被自动升级后整局死等。只有作者显式写了的合流才按合流序列化。

## 五、前端语法检查——两份闭环之一

- **前后端语法检查各自闭环、各有一份**（这不是重复，是根 AGENTS §二 的解耦设计）：前端是纯画图代码生成工具，不能没有自己的语法检查；compiler 是要独立打包带走的开源编译器，「哪个好人家的编译器不检查语法啊」。历史上两个缺口——compiler 漏了变量未声明检查、前端 run 漏调自带检查——均已补上。
- 前端报错走**统一链路**：所有检查点不再各自抛手拼字符串，统一经 reporter 分级——错误阻断（含行号、出错行、信息、区域，编辑器按行号高亮）、警告不阻断只黄条提醒。调试窗、报错条、日志全都吃这一份。
- run 按钮两道检查（作者原话：「run按钮：1检查多端，统一就放行到下一道坎，不统一就问。2. 检查语法，没错就交给后端compiler开跑，有错就报错——后面信息的返回两边不太一样：人类用femogen run按钮是femogen前端报错，ai调用femo-run工具是把报错信息返回给AI，谁触发就返回给谁。」）
- femogen run 按钮那套「到底跑哪个」的判断逻辑珍贵，femo-run 工具应复用同一逻辑（作者原话：「femogen run按钮的判断“到底跑哪个”逻辑珍贵，AI的femo-run工具也应该能复用那个逻辑」）。工程现状注记：AI 工具如今直调宿主开跑、不经过画布，这条原话的落实处是**宿主工具侧要做同样的事**（先问统一、再查语法、错误原样返回），不是绕开它。
- **与引擎镜像对齐是纪律，不是巧合**：变量未声明、动作五类硬校验、合流在环上警告、思考档位词汇、工具语义——改任何一边之前先看另一边的同款规则，两份闭环不许漂移；引擎侧新增校验时，前端同步补一份，反之亦然。
- 拦与放的边界（用户拍板）：**真语法错误拦死，「能跑的剧本不许前端拦死**。历史上「分支数爆炸」场景曾编译期拦截，后改为放行——用户坚持运行就应能跑；前端拦截权只留给确实无法解析/必然错误的东西。

## 六、干跑调试——零 token 验流程

- 调试器的原理是**假宿主**：AI 与人类节点由调试器替答，引擎真实链路一行不改。所以它测的不只是剧本 bug，引擎 bug 也能暴露；合成输入只验流程与接线，不代表内容质量——台词好不好取决于真正运行时的 LLM 表现。
- **调试范围跟画布走**：在哪个画布按调试就调试哪个范围——主画布跑整本剧本，模块子画布只跑那个模块。这是画布给调试器的独特贡献：模块单测不用写命令行。
- 三个入口同一台机器：画布调试按钮（仅插件模式提供）、CLI（femo2host/femoToolcall/femo_debugger.py）、MCP 工具。改调试器行为时三个入口一起想。
- 干跑跑的是**当前挂载的剧本**：挂载后又改过剧本，必须在编辑器里写入（或者如果由主 agent 负责干跑调试，需重新 `femo-mount`）再干跑，否则跑的还是旧版。
- 想撞随机分支/概率沉默：runs 多跑几轮（每轮换种子）；想复现某一场：seed 给同一个种子。跑满步数预算不是错误——持续循环型剧本的常态，报告里注明即可。
- 进阶调试 CLI（单测 module / 定向注入变量 / 概率沉默 / 注入无效赋值测重试链路）：`python femo2host/femoToolcall/femo_debugger.py run <剧本> --module 名 / --set 变量=值 / --assign-prob 0.7 / --flaky 0.3`（用法见文件头注释）。

## 七、运行状态机——事件驱动、快照校准、追平帧不表演

画布对「现在演到哪」的呈现，建立在三条裁决上：

- **权威在档案，事件只做增量（2026-10-05 画布直连改口径；2026-10-08 权威升一级到 runners）**。页面每次接通事件流（加载、断线重连、手机切回），先问引擎（健康口 runners→清单→跟随策略→档案）校准按钮与断点，再让事件流往上叠；「刚操作过按钮的短暂窗口内跳过校准」纪律照旧。**权威分级（2026-10-08 用户拍板「画布应该盯 runners，有多少收多少」）**：跟随着眼点=引擎内存里真在执行的场（/engine/health 的 runners，纯函数 pickFollowJob），盘上台账的 running 是「没人收尸的账」会有僵尸（实测 47:1），永不作跟随依据；档案只管「这场戏演到哪」的快照校准。台账 running 退出跟随口径的同一裁决里，观演登记表 3 条封顶同步退役——runners 有几场登记几场。**校准竞态闸**：SSE 一开帧就到而校准要两个往返——这窗口里的帧入缓冲，校准落定后按序重放（夹具实测抓到：帧早于校准、watchJobRef 渲染期同步晚一拍，两处都修了）。运行守卫仍问宿主（控制面）——显示校准走引擎档案，两者各归各。
- **追平帧只恢复状态，绝不表演**。重放帧（引擎重放环打 replay 标记、前端恢复期缓冲补放）不许弹浮层、不许驱动按钮——历史上挂起态刷新一次、整场历史的人类等待浮层「走马灯」弹一遍，病根就是历史帧被当成活事件。恢复本身是一场时序编排：校准未落定（插件模式还包括会话快照没恢复完）之前事件一律入缓冲，落定后按序补放——宁可排队，不许事件撞上空画布。
- **直播线自愈（2026-10-08）**：引擎 SSE 心跳是真实数据帧 {'type':'ping'}（15s 一拍，JS 可见——旧注释行浏览器看不见，已翻案）；画布健康看门狗除旁路健康口外，加帧龄判据——健康口活着但直播线 90 秒无帧（六拍心跳）=管道半死（TCP 无声断开，onerror 永不来），关旧线原地重订；老引擎心跳是注释行（健康口无 ssePing 标记）不启用帧龄判据，防误杀空转管道。后台切回（visibilitychange）这一拍立即重新校准——后台页计时器被浏览器冻结，帧龄看门狗在后台跑不动。
- **断点就是停在原地的亮点**。引擎每走到一个检查点，checkpoint 帧自带「位置+名字」（变量世界整包不上线——那是「现在演到哪」的快照，不是给画布看的账本）；运行中亮当前节点，挂起后亮点留在原地即是断点。画布会跟着戏走：事件落在别的子画布上时自动切过去，落幕自动回主流程。

par 并发下有一条专门的裁决：**人类等待记独立账本**。同一画布节点被多个并行实例共用时，AI 实例的事件会覆盖共享的节点状态、把人类输入面板冲掉（实测「闪一下就被 AI 气泡取代」）；人类等待载荷住独立账本，只有交卷与终态能撤下它。

## 八、主题与外观——token 单源

- 前端所有颜色（内联样式、SVG、注入的 CSS）一律引用主题 token（--femo-* 变量），**组件零硬编码色**。主题唯一定义处在 themes.js：换主题=切根容器属性+加一组 token 覆盖，不动任何组件代码；新主题只写与默认主题不同的 token，其余自动继承。
- 插件模式的样式是 scoped 的，不污染宿主主题；「跟随 DSH」档实时感知宿主昼夜切换。
- 加样式时先问一句：这个值是不是该进 token？两处以上用到的颜色、圆角、边宽一律进主题层，不许就地写死。

### 字体链与生僻字补字字体（2026-10-08 裁决）

- femoGen 全局要支持个别一般字体没有的生僻字，工具是一枚随包自带的补字小字体（仓库里那个几 KB 的 ttf）：它只收录这几个生僻字的字形，码表里也只有它们，别指望它当正字体用。接线裁决：**放进每条主题字体链的第一位**。浏览器画一个字时，是在该元素声明的字体清单里从头找第一个「有这个字形」的字体——链首字体对这几个生僻字命中出字形，对其他所有字（码表里没有）必然放手，字就滑落给后面的 DM Sans、MiSans、系统字体。命中即显示、命不中即回退：码表极小且只含生僻码位，决定了它放链首不可能截胡任何普通字，这是它天生的安全位置。
- 旧版为什么显示不出来：字体文件其实早就声明过了（告诉浏览器有这么一枚字体），但声明归声明，**没有任何一条字体链里写它的名字**。CSS 的逐字回退只在元素自己声明的清单里进行——声明了却不进链，浏览器永远轮不到用它，生僻字全部掉进后面的字体或豆腐块。还有一个隐藏层：dsh 插件模式的构建从门面直入、不走画布自己的样式管道，那份声明根本到不了 dsh 包——dsh 侧是双重缺失。
- 字体本体走**数据内嵌**：字体文件编码成文本直接写进样式，不再按文件路径链接。为什么：dsh 插件模式的画布没有 HTTP 面去伺服一个字体文件（链接必然落空），内嵌数据跟着样式走，三种形态（独立构建、托管成品、dsh 插件）拿到的都是同一份；代价是样式里多几 KB 文本，换来「所有形态必然生效」。注意数据必须收成单行——样式字符串里的裸换行会让整个声明被浏览器当坏语法整条丢弃（2026-10-08 实测抓到过）。
- 唯一事实源在 themes.js 的字体数据常量（由 common.jsx 的全局样式注入点带进所有形态——这个注入点是三种形态都必然经过的路）；画布独立入口的正文兑底链与四个介绍/文档静态页（不经 React）各自带同款内嵌声明与链首字体，保持同口径。换字体时：重新编码替换数据，单源一处加四页同步，重生成方法写在字体数据常量的注释里；新增字体链记得链首带上补字字体。

## 九、手机端——同一状态的第二种呈现

- 窄视口切到移动布局：**同一份状态、同一份核心计算，只是第二棵渲染树**。桌面与手机共用吸附对齐、节点联动、各面板组件；只有手势层各自实现。给桌面加功能时默认手机端也该有，除非它物理上不可能（如系统文件对话框开在电脑屏幕上，手机够不着——这时给手机端自己的替代入口，如工程目录浮层）。
- 触摸仲裁按「意图」裁决：落点只决定候选，位移才定终审——滚动意图一旦成立（位移过阈）就彻底放手给原生滚动，永不再拦；拖拽意图要「静止满时限」才武装，慢速滚动不被劫持。画布手势是登记制：只认落在画布内的触点，捏合锁定最近两指、第三指彻底无视。
- **性能铁律：手势帧直写 DOM，手势结束才回写状态**。每个触摸移动都触发渲染会让整树重绘（实测掉帧根因）；同理，任何高频更新（拖拽、流式、吸附线）都要先想「能不能不动 React 状态」。
- 手机端没有 hover，反馈语言是按压回缩+提亮；触摸目标按手指尺寸给足。

## 十、观测面——调试窗四页与日志哲学

调试窗四页分账：**脚本页**（运行事件与干跑流水）、**编译器页**（引擎打印的原文）、**FEMOGen 页**（画布自己的控制台输出）、**Host 页**（宿主插件代码的输出）。后三页的数据源在宿主进程，改那部分要重启宿主才生效。

观测面三条哲学，加新观测点时照此办理：

- **多一路落点，不替代任何东西**。采集靠钩住现有出口（如 console），原行为完整保留——观测面是旁路，不是迁移。
- **观测面绝不反噬主路**。拉历史失败不影响实时流，采集异常不外抛——观测面的崩溃不许连累业务。
- **观测面不是档案**。内存环形缓冲、条数封顶、刷新即重来；要留档用复制键。

日志流要有节制：引擎的高频内部信号（变量世界快照、状态同步帧）不喂日志——刷屏会淹没真错误。级别由来源说了算，不由前端猜。

## 十一、导入导出与文件面

- 导入导出是画布的**原生能力**（2026-09-30 裁决），不属于任何一家宿主：插件模式走宿主回调，独立模式由画布打伺候方的路由。三样权威都在公共层 femoGenConnector、记录都住数据根：**导入账本**（导入过/导出过的历史，全宿主共一本）、**当前文件槽**（独立模式「正在编辑哪个文件」的文档锚；插件模式的保存地址归宿主会话账）、**系统文件对话框引擎**（dsh 与 web 同吃一份；标题/缺省名一律编码进脚本——中文项目名曾让脚本破戒变乱码，别改回内插）。
- 行为语义与 dsh 同款：导入两级（历史清单 → 浏览）；导出三态（有保存地址直存 / 内容未改动先提醒再问 / 首存弹框，桌面=系统对话框、手机=工程目录浮层，只准在剧本目录围栏内）。
- 画布上浏览器文件选择框只剩 web 宿主自动挂载一个用户（播种脚本按特定选择器找人），别给它加第二个同类兄弟。
- 移出清单只划账本条目，**源文件零接触**——图标与文案都按这个语义写，别换成垃圾桶。

## 十二、剧本文件与存放

- 剧本文件建议存放在 user_data/projects/。
- 剧本引用外部 python 函数（code 区 file:"路径"）：支持相对路径（相对剧本文件所在目录，需已保存有 path）与绝对路径；未保存的纯文本只能用绝对路径。
- 有外部依赖的复杂项目：新建文件夹，python 脚本、其他文件和 femo 存一起。
- 剧本结构（meta/actors/vars/action/mainflow/code）、scope 语义、冷门语法——以根目录 语法文档.md 为唯一权威，不要凭印象猜。

## 十三、模块红线

- 语法检查的前端闭环不许绕过：run 按钮必须先过语法检查再开跑（历史上漏过调用，已补）。
- 「当多端剧本不统一时到底跑哪个」的判断属于前端，改动时不得删除或弱化——AI 工具侧要复用它，不是绕开它。
- 画布不自动回写文本：定稿必走显式按钮（§三）。任何「自动同步」「静默兜底」的提议都先对照 2026-08-22 裁决。
- 图文往返不许丢东西：文件头注释、排版坐标、「未声明 vs 显式选择」的语义区分（§四）。
- 两份语法检查闭环不许漂移：改一边，对照另一边（§五）。
- 人类等待面板不许被并行实例冲掉：独立账本机制不许拆（§七）。
- 观测面不反噬主路：任何采集/订阅的失败都不许外抛连累业务（§十）。
- 画布只生成、只预览：它是编辑器不是输入席，人类输入入口见 hostAdapter/AGENTS.md。
- 主题颜色进 token，组件零硬编码色（§八）。

## 十四、模块测试

- 画布相关测试在 developer/tests/：femoParser.test.mjs、femoGenerator.test.mjs、femoparser_validation.test.mjs、femogen_notice.test.mjs（Node 标准测试框架，直接 node --test 跑）。
- 改前端解析/生成逻辑 → 上述 Node 测试必跑；改了语法检查 → 对照 compiler 侧 test_var_decls.py 等确认两份闭环一致。
- 测试的面优先盖**纯计算件**：解析、生成、变量规划、吸附几何都是无 React 依赖的纯函数，天生可单测；新增此类计算件时照此办理，别把它埋进组件里。
- 画布 UI 本身没有自动化测试——真页目检是金标准；改手势/布局时桌面与手机两端都要过一遍。
- 干跑全流程验证用 femo_debugger.py（见 §六），零 token。
