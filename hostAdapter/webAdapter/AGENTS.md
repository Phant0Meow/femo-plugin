## 一、全景：接一家官网到底动什么

核心裁决一句话：**网站知识只住站点包，机器只认 `sites.mjs` 注册表**。所以接一家新官网的工作量 = 一个新文件夹 + 五处登记，机器层（`server/`、`extension/`、`console/`、`shared/`）零改动——这是设计承诺，`tests/site-boundary.test.mjs` 机械锁死。

| 文件 | 动什么 | 什么时候动 |
|---|---|---|
| `sites/<域名>/site.mjs` | **全部网站事实**（契约件清单见 §二） | 侦察后建初稿，取证后回填 |
| `sites/<域名>/inject.js` | 网络探针（取证期）→ 网络闸+流解析器（转正） | 探针期先抄成例 |
| `sites/<域名>/content.js` | 页面探针（取证期）→ 会话页代理（转正） | 同上 |
| `sites/<域名>/SITE.md` | 给人读的事实全谱 + 同源 checklist | 建包时立，随取证更新 |
| `sites.mjs` | import 一行 + 登记册加一名 | 建包当天 |
| `manifest.json` | `host_permissions`、`content_scripts[].matches`+`js`（站点包的**登记镜像**）、转正时补 bubble 段 | 建包当天 + 转正时 |
| `tests/site-boundary.test.mjs` | `SITE_DIRS` 加一名 | 建包当天 |
| `readme.md` 结构树 | 加一段 | 建包当天 |

流程是两段式：**取证模式**（`PROBE_MODE=true`，探针先行，不立席位不亮悬浮球）→ 拿回事实 → **转正**（换正式脚本，`PROBE_MODE=false`）。纪律：取证前不许把猜测写成事实——推测值在 `site.mjs` 里逐条标注，错了无害（探针站不立席位）。

## 二、要提供哪些字段（site.mjs 契约件清单）

站点包的心脏是 `site.mjs`，机器要的证件一件不能少（`site-boundary.test.mjs` 会逐件点名）。每件都写明「怎么探索」：

| 契约件 | 语义 | 怎么探索 |
|---|---|---|
| `SITE_ID` | 站点名，**=文件夹名**，会话引用的前缀、席位账的站点格 | 取浏览器地址栏里的正规门牌（curl 看双域名最终落到谁） |
| `SITE_URL` | 站点首页 | 同上 |
| `SITE_MATCH` | 扩展注入与标签页查询的通配 | `https://<门牌>/*` |
| `SITE_FENCE_RE` | 侧栏围栏正则 | `/^https:\/\/<门牌转义>\//` |
| `PAGE_SCRIPTS` | 本包要注入的页面脚本清单（manifest `content_scripts[].js` 的镜像；补注入按它来）。站点包脚本**路径带 `sites/` 前缀**（2026-09-27 归拢后的成例；写错边界测试会点名「文件不存在」）；`extension/seat-agent-core.js`（座席机器骨架唯一一份，2026-09-29 收编）排首位——content.js 之前，经典脚本按序注入同一隔离世界 | 取证期=探针对；转正=正式对 |
| `PROBE_MODE` | 取证与否（true=不立席位、不亮悬浮球） | 流程状态，转正翻 false |
| `SESSION_PATH_RE` | 从 URL 抓会话 id 的正则 | 打包包找路由拼装语句（见 §三）；实形以探针地址上报为准 |
| `SESSION_ID_RE` | 会话 id 本体校验（open-tab 帧防注入） | 探针抓到真 id 后照实写 |
| `sessionUrl(id)` | 会话 id → 会话页 URL（后台自动开页用） | 与正则同一形态，能拼回原样 |
| `COMPLETION_PATH` | 对话补全接口路径（网络闸拦它） | 探针抓正文时看哪条准时开火 |
| `API_PROBE` | 自家接口探针的宽匹配 | 打包包找接口命名空间（`-api/`、`/alice/` 这类） |
| `sessionRef(id)` / `parseSessionRef(ref)` | 会话引用拼/拆（`<SITE_ID>:<id>`，整串当 sid 全链流转） | 形态各站私有但当前三家同式；照抄即可，改形态只动本包 |
| `SITE_LABEL` | 显示名（报错文案、面板站点格用） | 人话 |

**会话名（席位显示名）** 不是 site.mjs 的字段，是 `content.js` 里站点私有的 `parseSessionTitle()` / `sessionTitle()`——来源因站而异，见 §六第 3 条。

## 三、侦察阶段：不动代码，先拿四样事实

完全公开渠道，一次半小时以内。真实命令示例（以豆包为例，替换域名即可）：

```bash
# 1) 门牌：双域名都探，看最终落到谁（文件夹名/SITE_ID 跟着它走）
curl -sL -o /dev/null -w "%{url_effective} (%{http_code})\n" https://doubao.com
curl -sL -o /dev/null -w "%{url_effective} (%{http_code})\n" https://www.doubao.com

# 2) 首页 HTML：拿 <title>（默认标题）与脚本清单
curl -sL "https://www.doubao.com/chat/" -o index.html
grep -o '<title[^>]*>[^<]*</title>' index.html
grep -oE '(src|href)="[^"]*\.js[^"]*"' index.html | sort -u

# 3) 主包下载（挑名字像主逻辑的，几十 KB 的 polyfill 跳过）
curl -sL "https://<CDN 主包地址>" -o main.js

# 4) 四连 grep——接口命名空间 / 补全嫌疑 / 领域词 / DOM 锚点
grep -o '"/[a-z0-9_/.-]*\(api\|chat\|conversation\|stream\|complet\)[a-z0-9_/.-]*"' main.js | sort -u | head -40
grep -o 'conversation_id\|chat_id\|section_id\|thread_id' main.js | sort | uniq -c
grep -o 'contenteditable\|chat-input\|chatInput\|data-testid="[a-z-]*"\|data-[a-z-]*input[a-z-]*' main.js | sort | uniq -c | sort -rn
grep -o '"\/chat\/"[^;]\{0,60\}' main.js | head     # 路由拼装语句
```

判读要点：

- **接口命名空间**是宽匹配（API_PROBE）的原料：deepseek 是 `-api/`、chatglm 是 `<xxx>-api/`、豆包是 `/alice/`——家家不同，以打包包字样为准；
- **路由拼装语句**最值钱：`"/chat/".concat(conversationId)` 这种语句直接给出会话页形态；
- **领域词计数**（conversation_id vs chat_id）告诉你 id 在响应里叫什么；
- 注意把**埋点/统计域名**记下来（如 chatglm 的 `sdata.chatglm.cn/...track`）——它们是探针抓取时要避开的噪音源；
- 静态侦察拿不到的（id 实形、接口真路径与流格式、DOM 真身）全部留给探针，`site.mjs` 里标「取证中」。

侦察产出 = `site.mjs` 初稿 + `SITE.md` 事实表（已确认/待取证两栏）。

## 四、探针阶段：PROBE_MODE=true，让事实自己上门

### 4.1 探针对怎么写

探针对成例抄 git 历史：`sites/www.kimi.com/` 的三轮探针版（4f8de22 前身，最全——含仪表破案）或 `c2d4497` 的豆包探针版（第一代成例），改四个词：守卫旗名（`__femoXxxProbe`）、日志 tag（`tag: 'xxx'`，会进服务日志的 `[ext:xxx]` 行首）、`API_PROBE`、控制台前缀。两件套的职责分工：

- **inject.js**（MAIN world，`document_start`，晚一拍就错过了请求）：
  - 接口探针：URL 命中 `API_PROBE` 就上报（去重在收端）；
  - 正文抓取：**只抓 POST 且 URL 含抓取词表**。词表是双向坑：**写宽了吃埋点名额**（chatglm 实案：抓取词 `'chat'` 撞上自家埋点域名，20 个名额在用户发消息前被吃光），**写窄了扑空**——RPC 风格路径（Connect/gRPC）不含 `stream/complet`，按侦察到的接口家族字样补词（kimi 实案补 `chat.v1`）；**头 4KB + 尾 4KB 双抓**（结束帧在流尾，只抓头会漏）；
  - **旁听读取一律增量排空**：边流边攒头尾，中断时把手头已到手的字交出去。页面（尤其 RPC 风格前端）会在请求完成的瞬间 abort 自己的 signal，`clone()`/`tee()` 出来的旁听分支共享中断态——一锤子 `text()` 会被连坐杀死整段交白卷（kimi 实案，见坑谱 14）；
  - 铁律：SSE 用 `tee()` 旁听、页面拿原样那份；任何异常放行原响应，探针绝不干扰页面。
- **content.js**（隔离世界，`document_idle`）：
  - 地址全形上报（pushState/replaceState/popstate + 定时兜底——SPA 换页不刷新）；
  - 输入类元素盘点（textarea/contenteditable/role=textarea，按可见过滤；目标站自家代码有输入区选择器的，往里查一层看真身——豆包的 `[data-chat-input]` 就是这么用的）；
  - 转播探针事件 → 服务日志（正文切段，服务端一行截 400 字）；
  - 捕获补全流 4 秒后自动采样：**最后一段大文本的祖先类名链**（回答容器锚点）+ **可见按钮快照**（停止钮锚点）。

### 4.2 manifest 登记（三处）

```jsonc
"host_permissions": [ /* 加 "<https://门牌/*>" */ ],
"content_scripts": [
  { "matches": ["https://<门牌>/*"], "js": ["sites/<域名>/inject.js"], "run_at": "document_start", "world": "MAIN" },
  { "matches": ["https://<门牌>/*"], "js": ["<域名>/content.js"], "run_at": "document_idle" }
]
```

取证期**不加 bubble 段**（悬浮球=机器公共 UI，在役站点才亮）。

### 4.3 取证三步（给用户的操作话术）

1. `chrome://extensions` **重载扩展**（清单变了）；
2. **重载后新开**目标站标签页，登录——已开着的旧页不会被注入（Chrome 只给新开/刷新的页面注入 content script）；
3. 随便发一条消息，等它回完。

**取证期用户该看到什么**：悬浮球**不亮是设计内**（悬浮球=在役站点才亮，转正才挂），页面里也没有任何可见变化——取证期的确认信号只有服务日志一条：`[ext:<tag>] 网络/页面探针已上线`。给用户话术时把这句带上，免得「没反应」被当成注入失败（kimi 实案）。

### 4.4 读日志（服务日志 `[ext:<tag>]` 行）

| 行 | 拿到什么 | 回填到 |
|---|---|---|
| `地址：/...` | 会话页真形、id 出现时机 | `SESSION_PATH_RE` / `sessionUrl` |
| `接口：POST /...` | 补全接口真路径、页面通道习惯 | `COMPLETION_PATH` |
| `捕获 …（头 n / 尾 m 字）` + `头[n]`/`尾[n]` | 流格式全文：帧怎么开张、思考/正文怎么分、结束帧长什么样 | 正式 `inject.js` 的解析器 |
| `[仪表] …` | 捕获分支每个决策点的自报状态与异常原文——**一条捕获都没有时先看这**（进没进分支、content-type、clone/text 报错原话） | 排障：照异常原文定案（kimi 三轮破案实录） |
| `输入区锚命中 / 输入类元素盘点` | 输入框真身（tag/id/class/placeholder） | 正式 `content.js` 锚点 |
| `回复文本块类名链 / 可见按钮快照` | 回答容器、停止钮锚点 | 收话兜底与忙碌态（**只在网络闸不够用时才需要**） |

### 4.5 DOM 收话锚点的收集轮（在役站补锚点；2026-10-02 八家实战定稿）

静默阶梯时代每家在役站包都要配 `domReplySelector`（领养收尾从历史 DOM 收全文）与 `domBusySelector`（忙锚消失判据）。补锚点不走「改代码重发版」，走**收集轮**：临时取证探针住各站 content.js 尾部（锚点转正后整段删除），用户只做两个动作——**重载扩展、刷新会话页**——证据自动进服务日志。已八家集齐（deepseek/chatglm/豆包/grok/千问/chatgpt/kimi/aistudio），流程与坑如下，照做可以让用户少重试好几轮：

1. **探针写什么**（成例抄 git 历史 11791a1/4f75f34/808049d 的 content.js 探针段）：
   - data-testid 全清单（按出现次数排）；
   - 叶子大文本块的祖先链（60 字起、祖先/后代去重、深度 10）；
   - 忙锚观察窗：每 2s 扫「停止/stop」语义钮，出现即报链（生成中才有的钮，**请用户顺手发条消息就能抓到**——chatgpt 的 stop-button、grok 的「停止模型响应」就是这么抓的）；
   - 解剖拍：对嫌疑容器（如 aistudio 的 `ms-prompt-chunk`）逐个报完整类名+末位两个的深父链——用户/AI 回复的区分类常在日志截断段之外，解剖拍一拍定谳。
2. **上报纪律：多行短句**。服务日志一行截 400 字——长祖先链切腰即废。每行 ≤380 字、一段链拆多行；流体类二进制转储按 170 字分段（JSON 转义膨胀近半，340 必超行限）。
3. **探针自报版本**：第一行打「锚点取证探针vN上线」。磁盘文件是新的、页面跑的旧脚本（重载没生效/页面没真刷）是高频疑案——日志见不见自报一眼定谳，别跟幻影较劲。
4. **可见性判定用 innerText，不用 textContent+类名过滤**：无障碍浮层（cdk-visually-hidden 一族）有盒子尺寸骗过 getBoundingClientRect、其标记还长在**父容器**上（被捡的叶子类名干净）——类名过滤滤了个寂寞、块配额全被浮层占。innerText 对 clip 隐藏元素是空串（textContent 不为空），渲染事实一锤定音（aistudio 四代探针才悟到，教训在坑 24）。
5. **打点用双时点**（加载后 8s+25s 各一轮）：重站正文渲染慢，5s 打点只照到壳（grok/aistudio/chatgpt 首轮全空壳实录）。
6. **挑锚纪律**：id/data-testid > 语义类名；哈希类名、动态 UUID（aistudio 的 `#turn-<UUID>` 每次加载变）、状态类（千问的 `qk-markdown-complete` 首轮有次轮无）一律勿锚。用户/AI 回复同住一个容器时（aistudio 的 ms-prompt-chunk、grok 的 message-bubble），区分类要**多例一致**才采信。宁可漏配（假阴性无害——退化「文本 3 拍不变」单条件）不猜配（假阳性卡死领养）。
7. **协作话术**：告诉用户「重载扩展+刷新某某站的会话页（挑有 AI 回复的旧会话），停十几秒再走」；可选加分项「发条短消息」抓忙锚。证据一到照单转正：锚点常量+装配参数两处改、SITE.md 事实表落账、临时探针整段删除。
8. **互斥纪律**：收集轮探针只住各站 content.js——`extension/seat-agent-core.js` 与 `server/runtime.mjs` 是共享骨架，别人可能在改（多窗口并行是常态），别碰。

## 五、转正阶段：换正式脚本，PROBE_MODE=false

照在役样板逐件换装（架构照 `sites/chat.deepseek.com/` 抄，事实用自家探针取回的）：

1. **正式 `inject.js`**：双闸（fetch + XHR 都架，很多站对话请求走 XHR，fetch 闸只看得见门口）只拦 `COMPLETION_PATH`；流解析器三个要点——SSE 按 `\n` 行缓冲跨 chunk 拼接、内容按类型/段分桶攒（chatglm 的 parts 分型是现成参考）、**段 finish 帧带全文要覆盖不要叠加**；结束信号以真页取证为准（deepseek 的 `FINISHED`、豆包系顶层 `status:"finish"`、kimi 的三层保险）；api 探针保留（上游换格式一次下发就能取证）。**逐字流发射（2026-09-28 起，转正即接）**：解析器快照（thinking/content）有变即发 `phase:'delta'` 事件——**全量快照不发差量**（覆盖帧天然消化），喂帧处发射、start 时清长度指纹防上轮残留（在役四家成例，发射点各 2~3 行）。
2. **正式 `content.js`**：只剩站点事实 + 一行装配——会话正则镜像、守卫旗、`INPUT_CANDIDATES`/`SEND_CANDIDATES`、`parseSessionTitle`，然后 `FemoSeatCore.createSeatAgent({...})`（机器骨架唯一活在 `extension/seat-agent-core.js`，2026-09-29 收编；此前的三样本事——身份/发送/收话——全在骨架里，站点差异全走参数：`domBusySelector`/`domReplySelector` 不给就不启用 DOM 兜底，**只认网络闸**；信口 `web-ping` / `web-deliver` 在骨架里）。**逐字流分支（转正即接）**：web-net 监听加 `phase:'delta'`——在飞回合（inflight）内 400ms 尾随节流上报 `{type:'delta', deliveryId, thinking, content}`，completed 补发终值（旁路轨：服务端喂 hub 草稿层，只上墙不碰收话时序；手工聊天没有 inflight 自然不发）。
3. `site.mjs` 回填全部「取证中」项，`PROBE_MODE = false`。
4. manifest 给该站补 **bubble 段**（悬浮球亮起）；`SITE.md` 去掉取证帽子。
5. **重启本地服务**（`node server/service.mjs`）——站点包是服务进程启动时装载的（ESM import 一次性），不重启则服务不认新站的会话引用；**重载扩展**；开会话页看服务日志出现 `seats: +tab …`。

## 六、坑与解法（三家实战沉淀，按踩的概率排序）

1. **经典脚本进不了 ESM**：content.js/inject.js 是被 manifest 注入的经典脚本（inject 还在 MAIN world），`import` 不了站点包——凡是它们需要的形态都内嵌一份**镜像**，并在两处注释里互相指名：会话正则的镜像住各 content.js；会话引用拼装（`<域名>:<id>`）已随 2026-09-29 机器骨架收编上移 `extension/seat-agent-core.js`（四家唯一一份，content.js 零镜像）。改站时照各 `SITE.md` 的同源 checklist 两处同改；`site-boundary.test.mjs` 会验证 site.mjs 侧那份的存在与正确。
2. **SPA 标题不等于会话名**：chatglm 的标题恒为「智谱清言」（首页 `<title>` 实证），直用 document.title 会让全场席位顶同一个名。名字来源按站取证三选一：标题动态更新（deepseek/豆包系，react-helmet）→ 直取；标题死的 → **搭页面自己请求的会话清单接口的便车**（inject.js 旁听响应收 `conversation_id→title` 映射，chatglm 包成例）；或站内有单查标题的接口。转正后第一场真演出看一眼席位名牌即知对错。
3. **抓取词表太宽喂了埋点**：探针抓取条件写 `'chat'` 这种宽词，统计/埋点请求会把抓取名额吃光，真补全反而没抓到（chatglm 实案）。抓取条件永远是 **POST + `stream|complet`** 级别的窄词。
4. **只抓头会漏结束帧**：结束信号在流尾。正文抓取一律**头 4KB + 尾 4KB 双抓**（滚动留尾）。
5. **很多站对话走 XHR 不走 fetch**：fetch 闸只看得见门口（deepseek 真页实证）。两道闸都架，共用同一套解析器。
6. **收话纪律：以网络闸为准，DOM 只做有实证的兜底**。「文本稳定几秒」是降级不是正解；没取证的容器锚不写进正式代码——闸没收到就大声失败，报错里带页面盘点（`describeEditors`），照着挑锚点，不猜。
7. **站点不明不默认任何一家**：open-tab 拆不出站点（旧裸 id 且无 site 格）就大声跳过。别加「默认第一家」之类的兜底——那是一家站点的私有判断长进公共层。
8. **受控输入框写入**：React/Vue 的输入框直接赋值会被骨架吞掉，必须走原型原生 setter + `input` 事件；contenteditable 用 `execCommand('insertText')`。发送先派 Enter（keyCode 13），发不动再点候选钮；候选按可见尺寸过滤（页面里常藏隐藏模板）。
9. **哈希类名勿锚**（`.fbb737a4` 这类）：改版即碎。锚语义类名、id、自家 data 属性、或网络闸。
10. **别碰宿主本体**：一切功能在本插件内实现（hostAdapter 守则红线）；探针/闸对页面只旁听不拦截、不改动任何请求与响应。
11. **新站注册后必须重启本地服务**：站点包注册表是服务进程启动时装载的（ESM import 一次性），只重载扩展不重启服务，服务就认不得新站的会话引用——症状一眼可辨：席位来源牌缺位、短 id 显示成整串引用的截断（实案：豆包席位显示「www.doub」= 老服务进程不认 `www.doubao.com:` 前缀）。服务端有按席位物理账 site 格补标签的回落，但自动开页等按引用认站的功能仍需新进程。
12. **浏览器会冻结后台标签页：页面探活必须带超时**：Chrome 内存节省器把太久没激活的后台标签页冻结（用户口中「网页太久没激活」），对冻结页 `sendMessage` 消息排队、promise 不 resolve 不 reject——web-ping 没超时就把 `collectTabs` 永久挂死，注册循环停摆（registering 旗不落），席位账冻结在最后一次成功注册的「全部在线」（「卡片显示在线却 30s 无回执」实案）。纪律：探活一律走 `pingTab`（3s 超时=不应答=休眠：登记在场但不在线，见 17）；运行/续跑前侧栏与操作台先打 `/seats/attendance` 点名（服务端发 attendance 帧催扩展当场 register，shared 的 `offlineRollCall` 判缺席拦截）——防「跑了才发现」。回合超时兜底在 `server/runtime.mjs`，是本宿主自有参数（网页通道公共层与引擎不知道；引擎侧对应 3600s 总兜底）：处置全归静默阶梯+保险丝（见 18 四次拍板与 22）——静默 30s 自动 reload、reload 无效 60s 提醒、执行保险丝 3000s ⚠️ 占位跳过不挂起；整轮上限 60 分钟（对齐引擎 3600s 兜底，冻结的页等人回来唤醒不该先死）。
13. **「在线」判定口径：两拍判死，补救后快速复查，手动重连兜底**：「当前」徽章是实时查的活动标签页（永真），「在线」是 10 秒一轮注册的旧账——两者没有互相校准，单轮 ping 失败就判死会让用户眼前开着的页也标离线，服务日志实证席位在 2↔3 席反复横跳（实案：chatglm 页每 20~30s 被补注入一次；同页还出过 `reinject failed: Cannot access contents`）。纪律：①探活首拍不应答先重试一次（600ms 后再拍）才交离线/补注入裁决；②补注入后脚本要几秒才立起来——3s 后自动快速复查一轮，别让救活的页再挂 10 秒离线；③探活各页并行，异常页不串行拖住整轮注册；④席位卡的圆点可点击（`web-reconnect`）：当场强探一轮（补注入绕过 20s 限流）并回最新账——离线灰点是主用例，自动补救失灵时人手一拍即活。
14. **旁听一律增量排空，页面会 abort 自己的 signal**（kimi 实案）：kimi 前端在每条 RPC 完成的**瞬间** abort 请求 signal，`clone()`/`tee()` 出来的旁听分支与原请求共享中断态——一锤子 `clone.text()` 被连坐杀死、整段交白卷（仪表原话「signal is aborted without reason」；对照组：页面没 abort 的 401 孤儿请求反而完整捕获）。纪律：边流边攒头尾，中断时交手头已到手的字（abort 前流已放完=完整捕获）；正式网络闸同守此律。逐字流的 delta 快照发射也顺这条走——abort 前流过的每块都已上报。
15. **探针静默失败先装仪表**：抓取/捕获分支里的空 `catch` 是第一嫌疑——clone 抛错、text() 拒绝全被吞成「一条捕获都没有」。给捕获路径每个决策点装自报（capture-debug 类事件：进没进分支、content-type、异常原文，不占抓取名额、照常旁听），一轮取证拿真凶再修——kimi 三轮破案全靠它（一轮全静默 → 二轮仪表定案 abort 连坐 → 三轮增量排空修复拿到全流）。仪表行进服务日志 `[ext:<tag>] [仪表] …`，读日志表有专行。
16. **open-tab 认站别只认席位物理账**（2026-10-01 实测）：请台帧的 site 只从席位物理账取，标签页从没在本代服务注册过就拿不到站点，扩展按「站点不明不默认任何一家」跳过——「自动开页」对关着的页永远落空（服务日志实锤 `open-tab requested without site (tab never registered…)`）。修法：席位没有就拆会话引用（引用自带站点）；裸 id 旧绑定两头都空，开不了页就说真话（点名行按 siteKnown 教重绑升级），不许假装开过。附带两拍：服务重启后扩展要几秒才握上手（SW 断线 3s 退避 + 10s 注册周期），点名在这空窗先等一手再下「扩展没连上」的结论；请台 30s 去重只记真递出去的，没递出的下一轮点名还该再试。
17. **「在线」不是席位的唯一健康态：页开着=在场，轮到谁唤醒谁**（2026-10-01 用户拍板）：浏览器内存节省器会杀后台页，六个网页演员不可能同时常驻在线——追「全员常驻在线」追不到，实案六席一秒内从全在线掉到四五个。裁决：席位账把两态分开记——`present`=标签页开着（冻结页也应答不了探活，但扩展按 URL 解析会话引用就认得出它，collectTabs 把不应答页照样上报、online:false），`online`=探活应答过、能立刻收帧（帧只发 online 席，派进冻结页=静默丢，见 12 老坑）；派工 `resolveSeat` 对「在册休眠」的席经唤醒闸 reload 叫醒（见 18）+原地等上线（等不到大声报错——引擎一切 error 挂起可续，唤醒网页后「继续」重演）；点名判据改「页开着（含休眠）=到场」——提前叫醒全场，等开演的几分钟里又冻回去，白醒。席位卡四态：运行中 > 在线 > 休眠中 > 网页未打开。代价明账：每轮发言多付一次 reload 加载等待（约 5~15s）——这是「六页无法常驻」物理约束下的必然取舍。
18. **保活不成立，查岗收割才是正解：唤醒闸 + 收割轮 + 回合领养**（2026-10-02 用户定案）：Edge 对后台页的猎杀快到「6 连 reload 每页只活 1 秒」（真机实测）——任何「让页面一直活着」的思路（轮询保活、切焦点唤醒、alarm 自动切）在这个环境全都不成立，且抢焦点烦人。事实支点：**生成在网站服务端继续跑，客户端死活不影响；回复全文躺在会话历史里，reload 醒来就能收**。统一模型只看引擎 mailbox 派下来的任务回合（不问顺行并行）：①**唤醒闸**（server/keeper.mjs createWakeGate）——并发 reload 预算 2、排队 FIFO、上线或超时放行（6 连 reload 撑不住的根治；点名请台同走这个闸，不再一口气开 6 页）；②**收割轮**（createHarvestWheel）——帧推进入列、收到结尾出列（dropTurn 唯一终局口），报数轮转每拍查一岗：页没了重开、活着不动、冻着 reload；**分两相**：发送期 2.5s 快拍优先盯完（「彻底发出去再轮下一个」），流式期 15s 普通查岗，完事=网络闸 FINISHED 或忙锚消失+文本稳定，**正文收 DOM 全文**（历史完整回复，不赌续流半截）；③**回合领养**——reload 销毁收话机，页面每次加载 hello 认领在飞回合（已发送→领账收尾；未发送→原帧随应答重发，服务端不重推防双发）。**防双页同发闸（2026-10-05 补，j2713 豆包实案）**：open-tab 帧广播给所有扩展连接、同一会话会开出多个标签页——第二页 hello 来认领时，现役页若在宽限窗（45s）内还有活气（send-failed 的 15s 自动重试也算），不换页不重发、回 retryHelloMs 让它约半分钟后再来；活气静默超窗（现役页八成死了）才放行换页接管。实案病根：双页各持一张同单、各发一遍，还把回合 tabId 抢到别的连接上、静默阶梯两次 reload 全指错门（`No tab with id`）。纪律：唤醒与查岗共用 reload 预算（borrowBudget）；remind 只喊人不切页（浮层/系统通知，点通知直达=人工自愿；到点自动切已退役）；查岗收尾判据依赖 `domBusySelector`/`domReplySelector`，新站转正必须把这两件取证齐（见各 SITE.md），只认网络闸的站领养后收不到结尾（走 60 分钟保险丝）。
    **二次拍板（同日）**：reload 名单铁律——「发给谁就 reload 谁」（「mailbox 发过来的任务是啥你总知道吧」「连剧本全员是谁都不必知道。只需要知道当前需要谁就好了」）：注册巡检（collectTabs，名单是「所有标签页」）曾把**剧本外的休眠页**每 20s 枪毙一次，收割轮也曾把**正在收流的单成员页**打死（chatglm 页 FINISHED 前 35ms 被 reload，407 字回话到手交不出，job 2675 实录）——①注册巡检零 reload 从此立住（休眠页救治只归派工侧唤醒闸与侧栏手动重连）；②单成员不查岗。**三次拍板（同日，终局形态「顺次进行」，覆盖前锤的轮转设计）**：「运行中的时候，如果有并发，这样子轮询还是不好，容易被网站风控。所以我们干脆改成……Mailbox 那边不变，但是 Mailbox 的任务发到 Web Adapter 这边的时候，Web Adapter 改成顺次进行」「那就只 reload 一次，一直活动到收到完整的结束信号为止。然后再去看下一个活着没，如果没有活着就 reload」「reload 操作之前要检查那个页面活着没？如果本来就活着就不用 reload 了」——15s 查岗轮（createHarvestWheel）整体退役删除；runtime 立**顺次闸**：mailbox 任务到网页席位一个一个来，同一时刻至多一个任务占闸（占闸段=解析座位→推帧→回合收场），**闸忙时排队不解析座位**（轮到才看活着没——提前 reload 排队期间又冻回去，白 reload 还多风控暴露），闸内在线直发、休眠经唤醒闸 reload 至多一次；释放权唯一归回合收场（dropTurn 四路终局）。页面中途被冻结的恢复=30s 提醒喊人（点开即醒）+回合领养（页任何原因重载都从 hello 接回收话）+超时三道——无人值守自动查岗的便利让位给风控安全。回归锁：runtime 单测「顺次闸同席连发」「跨席闸忙不解析座位（轮到才唤醒）」「停演清空顺次队列」三件。
    **四次拍板（同日，终局「静默阶梯」，覆盖前锤「没有周期查岗」的过渡形态）**：顺次闸删收割轮后「正在生成的独苗」被冻仍无人管，先补过一版静默看护（已发送后 60s 静默→stall-check 探活，活着不动冻着 reload），用户当天终审定案四级阶梯（原话逐字）：「0.默认保活。 1.节点未结束，收不到内容 30 秒， 自动 reload。2.reload 还收不到，弹提醒。3.弹提醒还收不到，就等着，3000 秒超时，报 warning，运行到下一个节点」「所有这种场合，都不许结束femo，不是error，甚至不是warning，切个页面就救活了算什么error。warning并且到下一个节点，直到这个时候都不要停止引擎」。落码要点：判据翻新=「收不到内容」不是「ping 不通」（lastSignAt 活气打点：已发送/delta 都算内容）——静默 30s 发 `reload-tab` 帧**直接 reload 不探活**（能 30s 无内容还应答得了的页恰是假活，reload 正是救法；旧 stall-check 的 1.5s 单拍探活连误伤面一起删除）；reload **恰一次**不循环（防风控暴露、防页面没冷加载完又被 reload）；提醒**恰一次**且挪到 reload 之后（文案保留用户原话「请在浏览器切换到那个标签页，这样点开就能简单的把他唤醒」）；提醒后收钟死等，3000s 保险丝 ⚠️ 占位跳过。静默看护计时用「检查点重排」不用轮询：每站按当前 lastSignAt 重算到期时刻，活气刷新基点后到点自会发现没到线、按新基点重排——活气侧零挂钩，领养重推只刷新基点、reload/提醒额度是回合级的不随重推返还（防重推循环把提醒饿死，doubao 实案教训保住）。回归锁：runtime 单测「静默阶梯 30s reload 恰一次→reload 后仍无内容才提醒→之后死等」「reload 后 hello 领重发帧重走发车」「有活气不 reload——静默基点随内容刷新」三件。
    **五次拍板（同日，救援 reload）**：四次实案（job 2683/2684/2687 豆包、2687 DeepSeek）证明这台机器的冻结快过流程——一次 reload 的活跃窗口（几秒）不够走完「写输入框→发送→收话」，回合卡在「已发送未完成」干等 3000s 保险丝。用户拍板「嗯，追加吧」：阶梯③站在提醒之后——**静默满 120s → 救援 reload 恰一次**（turn.rescued）。风控账：回合 reload 总数 ≤2、不循环轰炸；且救援只对帧已推进的回合（park 漂账不进阶梯，维持现状）——「已发送未完成」的回合生成在网站服务端继续跑、回复躺在会话历史里，救援 reload 让页面再活几秒走 hello 领养→DOM 收全文。修正案：阶梯④站收钟死等不变；提醒文案「已自动刷新一次」改「已自动刷新」（救援后是两次）。回归锁：runtime 单测四站全链（30s reload→60s remind→120s 救援→死等，reload 总数 ≤2 不循环）。
19. **闸匹配=路径全等，不子串包含**（2026-10-01 chatgpt 实案）：上游在补全接口同一前缀下添了兄弟端点（chatgpt 的 `/backend-api/f/conversation/prepare`，sentinel 预备包、POST 非 SSE），子串包含把它当补全本体拦下——JSON 响应走「非 SSE=即时结束」支路发出静默 done，座席在真补全流开演前就误判「生成已结束」，症状=「回复已结束但网络闸没有收到正文」而页面明明答了（job 2670 实录，09-29 首次真派工即同病）。修法：闸匹配先剥 query 再按 pathname 与 COMPLETION 全等；兄弟端点交给 api 探针逐条上报留痕。谁家的闸谁家改，chatgpt 的 `gatePath` 助手现成可抄。其余七家在役站点的补全路径与各自站内别的前缀无重合，本轮只修 chatgpt；后续改闸一律按此纪律。
    **【待收编账（2026-10-02 立项）——inject 闸骨架八份互抄，收编姿势照 seat-agent-core 先例】**：网络闸的共性机器（fetch/XHR/WS 三闸包装、字节缓冲、delta 全量快照发射、api 探针留痕）在八家 inject.js 里各抄一份——漂移已经实际发生（本条的「路径全等」裁决 chatgpt 一家先修，其余七家「本轮只修 chatgpt」就是漂移实证）。应照 2026-09-29 seat-agent-core 的收编姿势：`extension/inject-core.js` 单文件库（经典脚本无 import、PAGE_SCRIPTS 首位注入 MAIN world、globalThis.FemoNetCore 交接），站点包 inject.js 瘦成参数+私有解析回调（`createGate({ completion, apiProbe, splitChunk })`——各家流格式/结束信号是站点事实，留站点包正身）。**缓做的理由**：八家在役全靠真帧回归锁护着，收编是大手术；契机=下一次新站接入（新站按新骨架写）或某家改闸时（该家顺手迁移），逐家迁、迁一家跑一家回归锁。「各家不同留 sites、各家相同收骨架」的原则本身已是本包现行法：页面座席机器（身份/发送/收话机/直报）早已收编 seat-agent-core，剩下的就是这一块。
20. **matchSite 认门牌再抽 id：同形会话页不串门**（2026-10-01 实案）：grok 与 chatgpt 的会话页同为 `/c/<UUID>`，注册表只按会话正则匹配、chatgpt 排在前面，grok 标签页就被派成 chatgpt 包——页面跑着 cgpt 座席、job 选角账把 grok 的会话记成 `chatgpt.com:` 引用（job 2657 实录）。修法：matchSite 先过 `SITE_FENCE_RE` 门牌门、再在本家门牌内抽会话 id；回归锁在 `tests/site-boundary.test.mjs`（同形地址逐家归属断言）。
21. **唤醒即派要等页面就绪：「元素在页」≠「元素可用」**（2026-10-01 job 2672 实案）：唤醒闸 reload 叫醒休眠页后马上派帧——座席代理上线（脚本已注入、可收消息）只要几秒，但页面冷加载要更久，派帧时 DOM 已挂出输入类元素、可见尺寸过滤全落空，一拍 findInput 不中立即报死：「找不到任何可用输入框。页面输入类元素盘点：{盘点里明明有 textarea 和 ProseMirror}」——节点的重试把同一张冷加载页面打了八遍、遍遍同报（盘点就是证据：元素一直在、一直没布局完）。修法：deliver 先走 `waitForInput`（每拍重扫全部候选——元素可能先挂隐藏模板、布局完成后才可见；上限 20s，覆盖唤醒~就绪的常态 5~15s，也在服务端发送期 120s 保险丝之内），首拍即中零等待；上限内仍无=真问题（选择器失效/页面没输入区），响亮失败文案改成「等 20s 输入框仍未就绪」+原盘点，不静默兜底。纪律：凡「唤醒后马上要用页面」的动作，先等就绪再动，不把冷加载当故障报。
22. **「切页面就能救活」的场合永远不是 error，引擎一次都不许停**（2026-10-02 用户多轮拍板，违者按回退论）：冻结/发不出去/唤不醒这类页面可达性失败，一律走「自动 reload → 弹提醒（全页面贴顶横条）→ 回合保活等着 → 3000s 保险丝 ⚠️ 占位跳过、剧本继续」，绝不 actor_failed/挂起。处置全归静默阶梯（见 18 四次拍板）：①帧推进后全程（发送期+生成期+领养收尾期）都在阶梯管辖区内（推进即武装，不等「已发送」）；②发送姿势失败（输入框未就绪/未清空/生成未启动，doubao/GLM 三次挂起实案）——上报 `send-failed` 非终局（服务端当活气打点，提醒额度留给阶梯第②步），引擎不停；页面侧 **15s 自动重试链**（2026-10-05 用户拍板「如果没喂成功，15 秒重试；发出去了就停，后面的问题不纳入这条重试」——成功信号=sent（输入框清空或生成已启动），没见到就每 15s 重喂一拍；429 无虞：发送失败阶段没有任何请求到达站方，重试只动本页 DOM，生成真跑起来 busy 挡重发；外界兜底=3000s 保险丝关单撤钟）。send-failed 同时刷新静默基点——**重试中的页不被阶梯 reload**（reload 只会把冷加载计时清零，j2713 豆包实案：旧法一次性 focus 重试等一个不会来的人工点开，两页双败后阶梯 reload 又把页面打死回冷加载）；阶梯退居页面真死（活气断线）时的接管路径，30s 静默 reload 后 hello 领重发帧重新发车；③唤醒失败（resolveSeat 抛错）——`parkWakeFailedTurn` 立账+**立即**提醒（已等过唤醒闸 75s，不再静默 30s）等保险丝；重试牌唤醒失败同款 park（attempt 入账保 deliveryId 对号）——不再干等引擎 3600s 全程无声；④收话失败与领养收割失败（等回复超时/正文空）——页面降级留痕**不上报 error**（回复全文躺在会话历史里，reload 领养走 DOM 全文可救；2026-10-02 用户定案把「正文空」也划出 error——「闸说讲完了正文是空的」不再算真内容级失败）。页面侧 error 上报已全部退役；服务端 `error` 契约与 actor_failed 通道保留给真终局（挂队溢出等）。⑤席位队 parked 帧（busy 卡死——页面的 busy:false 上报会丢、或席位掉线）同样进阶梯：30s 静默 reload → 复活链（页面起来 → register → pong 把 busy 清回 false → pokeSeat 补发）→ 60s 提醒，不再整场干等 60 分钟零动静。配套纪律两条：park 回合是「漂账」（帧从未推进、无 connId、sessionId 留空——别用 seats.list() 找 soul，物理账不存 soul、list() 不喂映射必扑空），hello 领养对不上号、reload 没有目标，阶梯对它无事可做、只挂保险丝；提醒横条的撤回（终局 dropTurn 与页面苏醒两处）**不许守着 connId 在场才撤**——park 回合/浏览器重启换连接两种场合定向必失败，一律广播撤（横条永不消失是实打实的「莫名其妙」）。提醒 UI=全页面贴顶横条（用户拍板「弹在所有页面」），一张都没弹出来才回落系统通知。
23. **FINISHED 在手也报不出去：完成上报不许隔着一拍轮询**（2026-10-02 job 2683 豆包实案）：回合的 reply 上报住在页面 1s 轮询里（awaitCompletion 睡一拍 → 发现已收口 → 收卷上报）——页面在「FINISHED 已处理完」到「下一拍轮询」之间的**亚秒窗口**被 Edge 冻结，147 字全文在手、`流收话（FINISHED=true）`都进了日志，reply 就是出不去；服务端只见流停（静默阶梯的 reload 按设计触发，机制全对），领养接回后站包没有 DOM 锚点（「收话只认网络闸」旧裁决的遗留）、续流又不重放，干等保险丝。用户的观察「刚打开过页面就收得到结束标记、后台待久了收不到」正是冻结时机的概率分布——新开的页冻结还没轮到它。修法三件：①`reportReplyNow`——FINISHED 的**同一拍直接交卷**（fresh 回合；领养回合仍归 adoptWait 的 DOM 全文优先路径），轮询只作后备；②回合账引入「消费」语义——直报置空 inflight，runDeliver/adoptWait 的 finally 加所有权守卫（只清自己的账，不许误伤后来回合）；③`offerDeliver` 同步受理——消息通道不再持有整个回合（原先是通道持有到回合收尾，reload 一断就报误导性的「帧投递失败」，发送其实早就成功了）。教训：**跨冻结边界的动作必须压缩进同一个 JS 任务拍**，「完成判定」和「完成上报」之间不许有可冻结的间隙；配套地，站包的 DOM 锚点（回答容器/忙锚）在阶梯时代是领养收尾的救命绳，「收话只认网络闸、DOM 不需要」的旧裁决全部翻案——八家在役站包按领养盘点探针（祖先链已带 id/data-testid）逐家取证补齐。同日二连（job 2684 豆包 _5 实案）：**send-failed 之后不许丢回合账**——半醒页面上的发送会迟到（解冻续跑→Enter/点击生效比 3s 判定窗慢），旧法 send-failed 即清 inflight，迟到的发送成功（07:23:54 生成开始）和 FINISHED（07:23:58，89 字全文）成了无主回复，reportReplyNow 不敢认领，回复死在页面里而服务端保险丝还有两分钟。修法（用户再拍板「节点都没结束这些乱七八糟的地方在这儿瞎超时啥呢」——页面不许自设时限）：send-failed 后保留回合账，持有到 FINISHED 直报或服务端 turn-closed 关单帧（dropTurn 全终局出口广播 → background 转发各站点页 → 页面核对 deliveryId 放手并撤同单焦点重试）；超时的唯一权威=服务端 3000s 节点保险丝，页面零自设时钟（3100s/2min 两道草案均废）。runDeliver 的 finally 所有权守卫让位（keepInflight 旗）；同单 focus 重试放行（offerDeliver 同 id 不拒），生成在跑时照拒（迟到发送已生效，重发只会双发）。

24. **提醒的「切过去」必须切得动：寻址与落点账三件套**（2026-10-02 用户实点「按了没反应」）：横条按钮与系统通知都是「人工自愿切=抢焦点」的落点，三处全断过——①落点账（提醒指向哪个页）住过 SW 内存单槽（remindTab / remindTabClick），SW 一休眠清零，用户隔一阵才点=账已空、静默没反应（MV3 顶层代码重跑，坑 12「SW 会被浏览器休眠」同源；connId 早懂这个理住 storage.session，提醒账漏了）；②park 降级（唤醒失败）的提醒帧 tabId:0、sessionId:''，即便账在也无页可切——修法=service.resolveSeat 抛错尾缀 ref=<会话引用>、runtime park 提醒帧回填 sessionId；③tabId 缓存失效（页关过重开）无第二落点——修法=点击时按引用现场重认（matchSite 认门牌 + URL 含会话 id），认不到响亮留痕不装成功。定案三件套：**落点账住 chrome.storage.session（跨 SW 重启、关浏览器即清）＋提醒帧必带会话引用＋点击时现场认页**；寻址全无的提醒（如「查无座位」）由 canSwitch 不画按钮——诚实 UI，不留死按钮。回归锁：runtime 单测「park 提醒帧带会话引用」。**提醒会过期（同日用户补刀）：目标页被用户激活即过期——切页激活（onActivated 一拍，tabId 失效按引用现场认页）/到货时目标页已是激活页（不弹）/人工「切过去」成功三处收口，全局收横条+清落点账+清同单系统通知（过期提醒不再挂着喊人）。**

24. **锚点收集轮四代探针的坑谱（2026-10-02，八家实战按踩的顺序）**：①祖先链深度 6 截在消息层外（kimi 回复全裹在 toolcall 壳里，消息级容器没照进来）——探深到 10；②服务日志一行 400 字截断丢证据——多行短句；③类名过滤滤浮层滤了个寂寞（cdk 浮层标记在父容器上、叶子类名干净）+浮层有盒子尺寸骗过 rect 检查——**innerText 判可见**（clip 隐藏元素 innerText 为空串）是唯一稳的；④打点太早正文没渲染——双时点 8s/25s；⑤「磁盘是新脚本、页面跑旧的」疑案——探针版本自报；⑥静态侦察（打包包 grep）推出的锚点会被真页打脸（chatglm 的 `markdown-body common-answer` 是另一创作面的类）——**侦察级证据必须经真页盘点校验**；⑦忙锚观察窗没等到=用户没在页面发消息——要抓忙锚就明说「顺手发条消息」；⑧锚点转正后临时探针必须删干净，删的时候注意同文件尾部可能还住着别的常驻探针（流式诊断心跳，2026-10-02 拍板常驻），按段标记删、别整文件清尾。
