## 一、为什么改架构（病根与病例）

病根一句话：**引擎是多实例的（每座桥肚子里一份，挂靠表只在本桥内存），而信封地址只有宿主名一个词**。谁先捞到信算谁的，捞错的桥不但销毁信还把台词贴上幕布。

病例（job 2585，2026-09-25/26，全部有日志与档案实证）：

1. **回信被野桥捞走销账**：两座 zcode 桥（本窗的与隔壁旧窗残留的）都轮询信柜出站口；小猫咪（dsh-3081 本尊出演）的回信被野桥先捞，喂自家引擎被拒（job_not_active：档案在共享盘写着 running，但挂靠只在正确那座桥的内存里），野桥**无条件销账**（femo_bridge.py 出站轮询里销账在喂入结果判断之外），**并且照样投影上墙**（方法头注释承诺「引擎真吃了才投影」，代码没兑现）。引擎空等 3600 秒空放，台账留下小猫咪的空台词。
2. **隔壁窗口冒领 main 的信**：`gateway.port` 是全体网关共抢的一张纸（每网关启动覆写），所有窗口的钩子都打到最后启动的那个网关；钩子按会话号查绑定账、没绑的会话一律当 main 拉信——于是隔壁窗口的钩子经本窗网关领走了开场料包，以导演口吻代答（台账里的「李鬼」收尾词就烙着这痕）。
3. **投影行宿主标错**：行的 host 字段按「整批投喂者自称」盖章（_normalize_row 的 source 语义），贴行的是 zcode 桥，小猫咪的段就盖了 zcode；段键倒是按投递事实算对了（dsh-3081）——设计稿《投影宿主标注修正设计》只实施了一半。

`state=finished`、`error` 空——引擎的账说「圆满」，账本里的内容说「事故」。这正是「账本不骗人」要治的病。

## 二、目标形状（谁管什么）

```
每数据根一个常驻引擎进程 femo_daemon.py（脱离一切窗口，闲时不散场）：
  引擎（装配段从桥纯搬入：JobManager/Runner/产信/出站轮询/投递员）
  ＋ 投影中心 hub（进程内库，进程内直连，不再借宿任何桥）
  ＋ 适配器注册表（名字+会话号+门牌+推送/自取，登记过期自愈）
  ＋ 事件推流（SSE，带归属闸）
发现账：hub.json 兼任指针（不造第二本）。看门：任何客户端惰性探活，死了顺手代拉（脱离母进程）。

各家适配器（dsh/zcode/deepseekweb/autoclaw）＝薄客户端：
  登记、翻译、演戏（本尊出演/子代理）、看戏（投影窗/网页）、收信（推送户装门铃，自取户按号取信）。
桥退役（过渡期降级为转发壳，见第五节第 2 步）。
```

**组件职权对账表**（这次事故的教训就是边界要写死）：

| 组件 | 只管 | 绝不管 |
|---|---|---|
| 信柜（mailbox.py + 磁盘信柜） | 点对点信的存储、领取、记账；投递员的名册协调 | 不知道投影的存在；不喂引擎 |
| 投影中心 hub | 广播账本（行/段/草稿）、视角与信任账、选角账、HTTP/WS 服务、登记簿 | 不喂引擎，**不写信托管**——网页人类席那封信由席位自己写，hub 只是那张信纸够得着的投信桌 |
| 人类输入席（投影页/投影窗/终端席） | 写信的简易客户端：订阅等待态，自己把信封写全（收件人=等待态的宿主+会话号，凭据=wait_key），投进信柜存信口 | 不需要知道引擎在哪 |
| 常驻引擎 | 跑戏、产信、出站喂引擎（全世界唯一一张嘴）、投递上门、事件推流 | 不管各宿主怎么演戏、怎么画 UI |
| 适配器 | 翻译、演戏、看戏、收信 | 不生 Python 子进程，不碰引擎内存态，不自存投影历史（现状已是） |

三条通道纪律不变：事件管「现在」、信柜管「迟到的人」、幕布管「看见」。信柜只管点对点，广播归账本——这是用户纠正过的分界，写进铁律。

**写信自由，喂引擎一张嘴**：信柜的存信口对全员开放——适配器交卷、CLI 手写信、终端席、人类输入席网页都是寄件人，信封由寄件人自己写；唯一垄断的是出站，喂引擎的嘴全世界只有信柜管家一张。现状要拆的一处：hub.human_input 今天「校验+代写」一把抓——其中 409 新鲜度检查只是即时提示（权威校验在引擎侧的 wait_key+挂靠表，死信终态兜底），代写则挪回寄件人（网页自己写全信封），hub 端点降级为哑投信口（只机械入柜，不当作者）。过渡期这张口暂时还摆在 hub 的 HTTP 面上（网页唯一认识的地址），第 2 步起归常驻引擎。

## 三、六条结构性裁决（每条带为什么）

1. **信柜只管点对点、广播归账本**。混用会把排序去重视野问题请回来——那正是 hub 要消灭的病。
2. **信封升双词寻址**：加结构化 `target_sid` 字段（随信入账），不改 `target_host` 的语义。否决「宿主：会话拼成一个词」——投递事实账（dispatch_facts）记的就是这个地址，拼词会漏进段键把归属弄脏。匹配规则：信带会话号→精确相等才中；不带（旧信）→宿主级匹配（老行为）。
3. **归属单源=段键即事实**：行本体不带宿主字段，读的地方从段键取（`w:<host>:<wait_key>` 剖三段）。行 host 与段键是同一事实的两份抄本，两份必漂移；宁可读者改两处（网页徽标一行、渲染核同款判断）。设计稿《投影宿主标注修正设计》原案照落地，其「投影中心网页零改动」注记按实测勘误为「读者改一行」（实测投影页徽标读行字段 projection_center.html:1536，原注记与页码事实矛盾）。
4. **账本不骗人**：投影只在引擎真吃之后；被拒收的信立「死信」终态留档（`consumed` 的定义是「真吃掉」，拿它记拒收信是撒谎）。死信不回炉——引擎的等待超时与续跑是既定裁决，回炉只会热循环。
5. **事件归属闸**：订阅者按登记身份只收自己该看的场次事件。否则隔壁窗口的运行态会被别人家的戏点亮，冒领病的通道从事件面复发。
6. **发现一本账、升级不发明新机制**：hub.json 兼任常驻进程指针；看门=惰性探活+代拉；升级=诚实挂起（shutdown 现语义）+断点续跑（六关裁决现成）——不造守护进程，不做热接管。

被否做法（留档防复议）：包壳式常驻进程（两进程两本账的永久税）✗；双路灰度开关（双路代码活一天漂移一天）✗；地址拼词 ✗；第二本发现账 ✗；戏剧化命名 ✗。

## 四、会话号与收养（钉1/钉2 落地方案，探针已验）

- **号源用天然会话号，不铸造**。实测证据：钩子载荷原生带 `session_id`（网关探针文件 user_data/host-history/debug-stop-payload.json 实锤，双拼写都在；hooks/lib.mjs:54-57 取号、:77 随载荷上行——注释自认「钩子侧唯一有 CLAUDE_SESSION_ID 的地方」）。网关在 UserPromptSubmit/Stop 都能拿到调用方会话号，模型侧也能 `echo $CLAUDE_SESSION_ID` 经工具参数带回。网关进程自身拿不到会话号（possess 时代老账）不再构成障碍——按请求携带即可。铸造仅作「从未见过号」的兜底。
- **钥匙分发问题自解**：钩子自己知道自己的号，不需要著名文件，也不需要信件认领制。
- **收养规则从严**：收养的唯一合法凭证=**续跑登记**。resume 时续跑窗口本就要在档案登记自己——就在这一刻把导演格改成新号、并把该 Job 在柜的待领信重贴号。平时号不符=不领不记，信留柜，交给现有超时与清理兜底。「正在参与的窗口可收养」这类软判据被否——隔壁窗口也能自称参与者，等于给冒领开后门。
- **gateway.port 共享纸的处理**：过渡期保留（钩子只做拉信与注入，按请求会话号过滤后无害）；第 3 步适配器直连后此文件随转发壳一起退役。

### 第 2 步：引擎收编（v1 集成全家，唯一的大刀）

- 前置刀（零行为变更）：femo_bridge.py `main()` 装配段纯搬移为可复用的搭台函数——搬运纪律：一行语义不改，两处「顺序纪律」事故区注释逐条自证，全量 pytest+一场真演出护航后才进下一刀。
- femo_daemon.py 消费搭台函数：引擎+hub+信柜管家（出站轮询随装配段迁入，全世界唯一喂引擎的嘴）+投递员+注册表+SSE 同进程。
- 桥降级为转发壳：路由判据=命令碰不碰引擎内存态（挂靠表/运行器/worker）。碰的（job_start/job_resume/job_pause/post_speech/human_input/actor_failed/shutdown/mail_context/mail_catchup）转发常驻引擎；只读盘面的（get_job_state/list_jobs/list_scripts/get_soul/list_souls/check/ping）与干跑沙盒、编译检查留本地直调——干跑沙盒「永不碰生产」是结构性隔离，绝不因转发进常驻进程；常驻引擎死了编译检查也得活着。
- 壳的职责恰三件（2026-09-26 复审补，漏一件症状都是「戏莫名演不动」）：①转发命令（上条）；②**转播事件**——订阅常驻引擎推流，把引擎事件按原形状经 stdio 再播给适配器（适配器全程冻结，事件断了 dsh 记账/画布断点灯/逐字流当场全瞎）；③**代登记门铃**——投递员搬进常驻引擎后不认识各宿主的门，推送口信息（如 FEMO_PUSH_PORT）只在壳的环境里，壳启动时向常驻引擎登记本宿主门牌+续期心跳。

- 投递员：按注册表上门；没门铃的目标留柜自取（zcode 语义不变）。
- 适配器与测试全程冻结：桥壳对上仍是 stdio，四百多项测试一行不改。
- 验收：①关掉开演的 zcode 窗口，戏继续演完（进程表实证常驻进程还站着）；②双窗口不再互抢（信柜管家唯一嘴）；③全量 pytest 每步全绿；④真演出一场；⑤杀常驻引擎→代拉重生→在跑的戏能落到挂起→续跑过六关（「懒对账」在新进程启动路径上的落点实测钉死，2026-09-26 复审补）。
