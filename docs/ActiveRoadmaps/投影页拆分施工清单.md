# 投影页拆分施工清单

> 2026-09-26 立项，当日完工。把 2159 行的单文件投影页（femo2host/projection_center.html）拆进
> femo2host/projectionCenter/ 文件夹。本清单记录裁决、布局、搬运纪律与验证门，供后续接手者对账。

## 一、背景与病根

投影页从 2026-09-19 落地一路长到 2159 行 / 132KB：CSS 两层约 762 行、页面骨架约 60 行、
主脚本约 1310 行，六七个互不相干的功能块挤在一个经典脚本里。已经出现失控前兆——
`updateJump` 同名定义了两遍（旧 1224 与 1232），后一版无声覆盖前一版，而这正是修过三轮的
「刷新即扎底」老 bug 的病灶所在；单文件里它是无害死代码，再长下去就是事故现场。

## 二、裁决翻案记录（按仓库纪律先取得作者点头，2026-09-26 本窗对话拍板）

1. **「单文件」裁决退役**。页面头部注释曾写明「hub 只按固定路径伺候本文件，没有静态目录服务，
   所以主题不拆独立 css——单文件在 http 与 file:// 下都活着」。拆分后 hub 改伺候文件夹
   （白名单路由，见 §五），三处旧注释（原 9-19、405-406、1340-1341）随拆改写，不让文档骗人。
2. **file:// 直开正式放弃**。这个兼容在 2026-09-24 引入共享规范件模块引用时就已经名存实亡
   （file:// 下模块加载必败，render 空转永不绘制），拆分不再为它保留任何东西，只把话说破。
3. **共享规范件改静态引**。单文件时代的「module 垫片挂 window + HRC() 就绪闸门」整体退役，
   各模块直接 `import * as HRC from '/host/hub-render-core.mjs'`。依据是全局红线「少兜底」：
   闸门空转本是静默吞错，静态引让装载失败大声报错。

## 三、方案来源与分歧裁决

方案经三方独立对账：两名子代理在互不知情、也看不到在途工作的前提下盲评（任务书禁读
projectionCenter/ 文件夹），加上先期落的第一件施工图（projectionCenter/state.mjs 文件头）。
三方在结构清点、语言墙（import 只读→共享账本对象）、updateJump 双定义、file:// 已死、
兜底路由吞模块 404 成黑页、零前端测试等结论上全部一致；评级同为「值得拆，难度中」。
分歧的裁决：

- **hub 路由形态**：取乙评估员的白名单表（文件集小而封闭，零路径穿越面，延续 hub
  「不做通用静态目录」的原口径），同时落实甲评估员的四条硬底线：统一 no-store（`_cors`
  本就全响应发放）、按扩展名给类型、`/pc/` 未命中回非 HTML 的 404 且注册在兜底之前、
  缺文件干净 404 不兜底回页。
- **模块粒度**：以在途施工图的七模块为底座（变量归属账已盘点完），从乙评估员处吸收
  「waiting 类小函数跟着 render 走并导出」以避免 render↔composer 成环。
- **no-store 之争的实锤**：hub 对一切响应发 no-store（`_cors`，projection_hub.py 的
  缓存注释记着 2026-09-19 实锤案例），`_page` 经由它享受——「改完刷新即生效」性质跨拆分保留。
- **pendingPlugins 的归属勘误**：它在 render 内部自产自销（从 rows 摘出并入最近段，WS
  分发器不碰它），归 render 私有是正确的；评估阶段「ws 直写」的说法作废。

## 五、hub 侧改法（projection_hub.py）

- `PAGE_FILE` 改指 `projectionCenter/index.html`；`_page()` 代码不动。
- 新增 `/pc/` 前缀分支（注册在未知路径兜底**之前**）：文件名在白名单表内才伺候，按扩展名给
  Content-Type（.html/.css/.js），未命中回 JSON 404（绝不能回 HTML——浏览器对模块强制 MIME
  检查，回 HTML 就是整页黑加一行报错、服务端零痕迹）；缺文件干净 404。
- 三个入口别名（`/`、`/projection_center.html`、`/index.html`）与未知路径兜底原样保留——
  autoclaw（index.mjs）与 deepseekweb（service.mjs）都硬编码开 `/projection_center.html`，
  selftest 断言 `GET /` 含 `Projection`（页面上「Projection Center」那行小字）。
- `_host_module`（/host/hub-render-core.mjs）原样不动，dsh 侧还要打包消费它。
- no-store 由 `_cors` 全响应覆盖，拆分不加不改。

## 六、搬运纪律（零自动化测试现状下的硬闸）

1. **函数体逐字搬运**：只允许三类改动——文件头 import、共享状态加 `S.` 前缀、模块私有的
   局部重挂。逻辑一个字符不改；评审按函数体零 diff 过。
2. **updateJump 只搬生效版**（旧 1232-1240，含它的 scroll 监听），死版（旧 1224-1227 及其
   监听）不搬——否则「渲染路径写旗」的旧语义复活，「刷新即扎底」老病复发（该病修过三轮，
   注释有案底）。合并处留一行注记。
3. **委托监听挂容器才活得过全量重绘**（旧 1788 注释原话）：席位内联三事件委托挂 `#tl`，
   折叠委托挂 document，谁也不许「顺手优化」成行级监听或单例。
4. **焦点/光标保卫与 render 成对**（旧 1293-1308）：抓焦点、写 DOM、接焦点三步不分家。
5. **顶层的「触发」全部收进 main 的 boot**：cast 轮询启动、主题初始化、connect、打字机 tick
   按序显式调用；模块顶层只留定义与监听注册（module 天生延迟执行，DOM 已就绪）。
6. **esc 唯一口**：渲染 HTML 的模块必须 import 同一个 esc，不许手拼本地简化版。
7. **shared 规范件静态引**：`HRC().x` 改 `HRC.x`，判空闸门全删（见 §二.3）。
