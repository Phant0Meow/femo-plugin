# 投影中心行协议（PROTOCOL v1）

> 权威实现：`femo2host/projection_hub.py`（单文件、纯标准库、零依赖）。
> 设计总纲见 `ARCHITECTURE.md` 与 `投影合一设计.md`——本文只管「线上字节」，
> 第三方宿主照本文接入即可，不必读实现。
>
> **版本：`proto: 1`**。WS 快照（ctrl:snapshot）与 GET /view、/health、/diag
> 响应都带 `proto` 字段。破坏性变更才 +1；新增字段不升版——客户端必须容忍
> 未知字段，向前兼容是协议的一部分。

## 0. 十分钟接入清单

宿主要做的只有三件事：

1. **喂**：演出中把整理好的行和直播帧 `POST /feed`（§5）；
2. **画**：投影窗 WS 订阅（或轮询 GET /view）拿行渲染（§6）；
3. **搭切换器**：GET /views 拿视角清单做下拉（§6）。

`job_id` 用引擎给的，不要自己发明（§7）。

## 1. 行（账本的最小单位）

| 字段 | 必填 | 说明 |
|---|---|---|
| `n` | hub 分配 | 全系统唯一排序权威（到达序=权威序），宿主给的版本号一律不作数 |
| `t` | hub 分配 | 毫秒时刻 |
| `host` | hub 分配 | **来源宿主名**（2026-09-19 联机改造）：由该批 feed 的 `source` 决定，单帧自报的一律不作数。**【2026-09-26 刀1 语义收窄】job 账本行不再写此字段**——行级归属单源=段键（`w:<host>:<wait_key>`，读端剖 `w:` 后首个冒号前段；裸键/非 w: 键无归属），场次 host 集与视角归属也剖段键；会话账本行保留（按宿主分格是账本语义本体）。旧账本行自带 host，读端 `row.host || 剖段键` 双态兼容 |
| `zone` | 否 | `inplay`（戏内）/ `outside`（戏外，只进上帝窗）/ `meta`（场次行，**全视角可见**——开演/续跑/落幕/暂停/出错是戏级公告，2026-09-21 用户拍板）；缺省或未知值归 `inplay` |
| `kind` | 否 | 见 §2；未知值原样透传，页面兜底渲染 |
| `actor` | 否 | 发言/归属角色名 |
| `text` | 否 | 正文 |
| `targets` | 否 | null/[] = 全员可见；列表 = 只进指定角色窗（与视角名按基形相交匹配） |
| `turn` / `step` / `session` / `node` | 否 | 溯源标注，hub 不解读。session 只是展示标签：hub 一律按 job_id 记账 |
| `toolCall` / `toolResult` | 否 | `{"name","arguments"}` / `{"node","output"}` |
| `src_seq` | 否 | 宿主幂等键（复合键如「子会话id#seq」）：hub 按 Job 查重丢重放，账本重载后依然有效 |
| `slot` | 否 | =1 预留空位（等 fill-slot 回填，§4）；页面不渲染空位 |
| `femo_session_id` | 否 | 引擎台账场次号（Chronica session，2026-09-29 新增）：**只由 hub 在 play_start/play_resume 行落账**（号随引擎 flow_start 事件到达，开演那拍即定）；其余行不吃这个字段。号归引擎（hub 不发号）——journal 是 job→台账场次映射的唯一权威，整场回放（§6 /chronica）与两本号对照都以它为准 |
| `items` | section 专属 | 段内条目数组，槽序由 hub 规整（见下）；item kind 词表见 §2 |
| `role` | section 专属 | 段角色标：`main`（主 Agent）/`ai`（AI 角色）/`human`（人类席位）——开段那拍喂方自报，显示策略据此分类（§1.6）；旧账无此字段按 `ai` 处理 |

**槽序定稿（2026-09-19 用户拍板：hub 是排序的唯一权威，宿主无脑照抄）**：一个节点实例 =
一个容器 = 一个行号。容器里的槽按——

  `showprompt`（演出提示）→ `prompt`（本节点指令）→ `name`（名字槽）→ 内容槽按发生序
  （`retry` 重试反馈 / `cot` / `tool` / `tool_result` / `say` / `fail`…来了什么写什么，
  出现才写、没出现不写）

头部三件套的位置由 **hub** 在落账时统一规整：喂方（常驻引擎/宿主）只管按到货顺序塞，hub 把
头部槽提到内容之前、showprompt 恒在 prompt 之前；**名字槽归 hub 独有**——按行上 `actor`
注入到 prompt 之后，喂方带来的 name 槽一律剥掉（actor 空=不插；空段不注入，空位行与
「正在…」空块保持零内容）；actor 晚到（seg-fill 带 actor）那拍名字槽原位补上。晚到的
兜底 showprompt（老引擎无 `blocks.showprompt` 时）也归位段首、只补一次（§4.5）。
页面顺序＝数据顺序，宿主与页面都不做任何排序、只按 kind 选样式。**早先「提问独立成行」
已废除**；**narrate 大杂烩也已废除**——新数据一律用真实类别当 kind，旧账里的 narrate
原样保留、渲染端兜底（加法变更，proto 不升版）。

**窗=读法，不是存储**：god=全部；stage=仅戏内；`actor:X`=戏内且 targets 空或含 X。
角色名匹配按基形相交（`@Eve（Eve）` 与 `@Eve` 互相命中）。

## 1.5 多宿主联机【2026-09-19 新增】

**场景**：dsh 与 zcode 等宿主共用同一本 Chronica、指向同一个 sessionid、各认领不同
角色——**共演同一场戏**。于是 job_id 相同、落盘仍是 `projection/<job_id>/` 一个柜位
（一场戏一本账），差别的只是每行要说得清来路。

- **`source` = 宿主自称**，取宿主能力清单 `host.manifest.json` 的 `host` 字段
  （`dsh` / `zcode` / …；缺省 `standalone`）。它随 feed 整批上来，落进每行的 `host`。
  引擎侧从清单读（`femoCompiler/host_manifest.py` 的 `host_name()`），宿主侧读同一份
  清单放进 `FEMO_HOST_NAME` env——**两边必须是同一个词**。
- **段键带 host**：`seg` 未显式给出时按 `w:<host>:<wait_key>` 合成。理由：同名角色的
  引擎令牌 `wait_key = f"{run_tag}ai_{node}_{counter}"` 里 `run_tag` 由引擎注入成
  `j<job_id>:`、`counter` 是**每个 Runner 实例**的计数器——共演同一场时两台 run_tag
  相同、counter 各从 0 起数，**令牌必然撞**。不带 host 段，两台的逐字流会落进同一个
  容器、字一字一字交错着长。
- **信任集按 host 分格**：`set_owner(job, sid, host)`，每台各登记各的 `host_ref`；
  跨会话过滤只认「本帧 host 那一格」的 sid。改前是单值 sid，第二台喂来的戏外行会被
  当"别人的会话"在 feed 期丢弃（不入账、页面也看不见）。
- **同名角色两个席位**：`/views` 里 id = `actor:<host>:<基形>`、key = `<host>:<基形>`，
  并附 `base`（裸基形）与 `host`。**显示名与 targets 里的名字永远是裸名**——`[dsh]`
  这类前缀只由渲染端拼（塞进数据会破坏 scope/靶向的基形匹配，角色窗当场空掉）。
- **host 一级一次，不重复到槽**（2026-09-19 用户三度校准；标签位置见下面 ②）：
  ① 归属：「**Host 它是角色的字段之一**」「不同的角色可能来自于不同的宿主」——
     所以同一个 hub 里可以共存多个来源，它**不是**整场的属性（别做成统计栏/场次头
     那种一处性的全局标签，那会看着像"整场只有一个来源"）。
  ② 位置：「**每个容器前面带一个前缀 dsh**，毕竟一个容器里的信息肯定是来源于同一个
     宿主的……显示为细细的一条就好了」；「我希望你在网页上显示的方式，还是**信实的、
     严格的体现 Hub 的数据结构**」。
  → 落地：**段行（容器）有 `host`、段内 `items`（槽）没有**——标签因此**一级一次**：画在**行头**（时间戳 · #编号 的那一行，`[dsh] 14:39:00 · #2`），
  容器头、正文、槽一律干净。不带容器的独立行（戏外框、单独 narrate、气泡）同样只在行头标一次。
  位置理由（用户）：「把那个宿主信息放在时间戳和编号那一行，好像能更好看一点」；
  场次栏（开场/落幕）不是某人的话，不标来源。
- **`/jobs`** 每项带 `hosts`（该场出现过的来源）；**`/diag`** 带 `hosts`（名册）与
  `owners`（本场 `host → [sid]` 信任账）；**`GET /hosts`** 单独给名册。
- 兼容：不带 `source` 的老宿主行为与改前一致（行无 `host`、段键 `w:<wait_key>`、
  信任集记在全局格 `''`）。`cast.json` 的 `owners` 是 `{host: [sid,...]}`，老文件的
  单值 `owner` 照读不误。

## 1.6 显示策略（VIEW_POLICY）【2026-09-20 新增】

**全局唯一的显示规则，是 projection_hub.py 模块顶的一个常量矩阵（`VIEW_POLICY`）**：
改这一处 = 改所有宿主的窗口显示。hub 在**出料口**（snapshot / WS 广播）按窗口视角
执行——宿主拿到的料包已按此滤好，渲染端无脑照画；账本原文分毫不动（/replay 永远全量）。

- **行 = 视角类别**：`god` 上帝 / `stage` 戏内 / `main` 主 Agent 角色窗 /
  `human` 人类角色窗（席位是人）/ `ai` 其余 AI 角色窗。角色窗的类别由 hub 从账本
  收出的段角色归属判定（actor:X 的 X 出现过 `role:main` 段=main 类、出现过
  `role:human` 段=human 类、否则 ai 类）——喂方不必另行登记。
- **列 = 受管内容（过程类）**：`main_prompt / main_cot / main_react`（主 Agent 段）、
  `own_prompt / own_cot / own_react`（视角本人的段）、`other_prompt / other_cot /
  other_react`（其他 AI 的段）、`human_prompt`（人类节段的指令 prompt 槽）。
  React 过程 = 工具调用 + 工具结果。
- **不受管**：**showprompt（演出提示）**——永远显示、所有视角都能看（2026-09-20
  用户定案「只显示 Show Prompt，AI 的 Prompt 全程不用显示」）；台词（say）、名字
  （name）、公告（notice）、旁白、重试/失败行同样不受管——可见性仍按 zone/targets
  老规矩；本策略只管「过程」，戏词永远公开。zone/targets 先裁，策略在幸存行上再剪，
  两道闸互不越权；草稿层（drafts）同尺过滤。
- **当前默认**：AI 的 prompt 三列（main/own/other）所有视角全 False；`human_prompt`
  在 god / stage / human 三行 True（2026-10-03 用户定稿：stage 的输入席也亮，题跟着
  输入席走）；cot / react 各行全 True。日后改显示规则，只动这个常量。
- **人类 prompt 的状态闸（2026-10-03 用户定稿口径）**：「prompt 只有人类输入的时候
  能看见。输入完就不用了」——视角列放行之外，还须该席**正在等待**（等待席位镜像
  在册，不读行 open——续跑世代键、human_wait 早于段落账半拍的窗口期，行态会骗人）；
  收口/历史人类节点的 prompt 一概扣下，showprompt 照在（它相当于 notice，永远公开）。
  等待中的人类节点 showprompt+prompt 都显示；等待中的 AI 节点只显示 showprompt
  （AI 的 prompt 发给它们但投影中心从不展示）。
- 剪空的行整行不投（不露「有货被藏」的空壳）。

## 2. kind 推荐词表

`say` 台词 · `showprompt` 演出提示（进节点的场景旁白；与 notice 同款隆重横幅） ·
`prompt` 本节点指令（引擎 `blocks.prompt` / `human_wait.prompt` 的原文，「等待你的回应：」
这类包装话归显示层；同构横幅换蓝——一眼认出「在等我」） · `name` 名字槽（段头，hub 注入，
喂方不许喂） · `notice` 公告（同款横幅） ·
`retry` 重试反馈 · `fail` 节点失败 · `cot` 思考 · `tool` 工具调用 ·
`tool_result` 工具结果 · `section` 回合段（一段一个行号，段落闸门） ·
`play_start` 开演 · `play_resume` 续演（引擎续跑重发 flow_start，产信端注 `resumed` 标，
投影分开写） · `play_end` 收场 · `play_paused` 暂停（断点保留可续跑） ·
`play_error` 出错（正文自带错误详情）——四个新场次 kind 与 `play_start` 同为
zone=`meta`，全视角可见（2026-09-21 用户拍板：所有投影窗都有 FEMO 开始/已跑完/
暂停/继续这类消息） · `whisper` 戏外语（警告/错误，仍只进上帝窗） ·
`narrate` 【已退役 2026-09-19】仅旧账兜底——曾经的旁白/反馈大杂烩，已按真实类别拆进
showprompt / prompt / retry / fail / notice，新数据不再生产。

未知 kind 原样透传。**扩展点是 kind，不是 zone**——不要为宿主私有心事新造
zone（未知 zone 会被归入 inplay，等于向全舞台广播）。

## 3. 直播块（打字机）【已退役 2026-09-19】

> 逐字流现在**一律喂进段**（§4.5 的 `draft-*`）：演员轮、主模型下场轮、导演轮
> 三条来路都是「往容器里填槽」。本节这些帧已无生产者；接收端保留观察几天
> （`/live`、`_live` 收尸、页面「输入中」计数同批），确认无 bug 后再连根删。

| 帧 | 字段 | 语义 |
|---|---|---|
| `live-start` | key, actor, blockKind(text/reasoning/toolcall), name? | 开块 |
| `live-delta` | key, text | 增量文本 |
| `live-done` | key, row? | 转正：带 row 用 row，否则按累计文本合成一行 |
| `live-drop` | key | 清块不转正（行由宿主交卷同拍负责） |
| `live-clear` | — | 场次边界清桶，广播 ctrl 让页面清屏 |

GET /live 返回块形 `{key, actor, blockKind, name?, text, act}`——`act` 为最后
活动 epoch 秒。宿主打字打到一半死掉的块静置超时（15 分钟）由 hub 收尸：清块
不转正，广播 `ctrl live-done` 撤页面幽灵块。

## 4.5 段与草稿层（槽的两态）

`section` 行是**段**（一个节点实例的全部可见内容 = 一个 n）。段里的内容叫**槽**，
槽有两态：

- **草稿（draft）**：正在写的那条。喂方把逐字增量喂上来，字一个个往里长；只活在
  hub 内存 + 旁账 `projection/<job>/drafts.json`（节流刷），**永不进主账**；
- **定稿（final）**：写完了的那条，就是段行 `items` 里实实在在的一条。

下行里段行多一个可选字段 `drafts`：`[{key, kind, text, name?, actor?}]`，排在 `items`
之后（页面画在段尾、带光标）。**没在写的段没有这个字段**。

**草稿的排序是 hub 定的，不按写入序**（2026-09-30 拍板）：喂方的 drop+delta 是两帧，
哪路有字哪路整对重发，写入序会在批与批之间翻面——照抄写入序，页面上的思考链/台词
行就跟着上下跳。hub 按**槽键 `kind#step#index`** 排出确定序：轮次（step）升序，同轮按
语义序（思考 cot → 工具 tool → 台词 say），同类按 index；无号段（`-`，整轮一次性快照
槽）垫底。渲染端拿到什么序画什么序，不许自己再排。同批内草稿的变化只在**批尾统一
广播一次**（页面只见批终态，不见 drop 的中间态）——批量上行口 /feed 的原子面。

| 帧 | 字段 | 语义 |
|---|---|---|
| `draft-start` | seg, key, kind, name?, actor? | 开一条草稿槽 |
| `draft-delta` | seg, key, text, kind? | 追加字（槽不在就顺手开一条） |
| `draft-drop` | seg?, key? | 作废：带 key 撤一条 / 带 seg 撤该段全部 / 都不带=全场撤 |

`kind` 用喂方自己的词汇（`text` / `reasoning` / `toolcall`），hub 归一成行词汇
（`say` / `cot` / `tool`）——喂方不必知道行词汇。

**两边都进、进去一个样**：容器可以由**常驻引擎**开（引擎节点轮：`ai_request` /
`human_wait` 那拍，令牌 = 引擎的 `wait_key`），也可以由**宿主**开（宿主自己的轮，
如戏外导演轮：user 发言那拍开、轮末收，令牌由宿主自造如 `h:<sid>:<seq>`）。
hub 不看来源，只看帧；两条来路进来之后是同一个容器、同一套填槽规矩。
**收口权归开容器的人**：引擎开的引擎收（落账那拍），宿主开的宿主收——谁开的谁收口，
另一个人碰它只会把草稿提前转正、再被定稿顶出双份。

两条规矩（喂方不需要自己防双份）：

- **吸收**：`seg-fill` 里出现某种 kind 的定稿时，段内同 kind 的草稿整条丢弃；
- **转正**：段收口（`seg-fill` / `seg-close` 带 `open:false`）时，还没被吸收的
  草稿就地变成定稿（喂方没交卷也不丢历史）。

**段键由喂方自报**（引擎用 `w:<host>:<wait_key>`；别的宿主用自己的稳定键），hub 只要求
「同一段的键稳定唯一」。草稿可以先于 `seg-open` 到达（两条路各有先后）：hub 先
记下，开段那拍带上；已收口的段不再收草稿。

**宿主用 `wait_key` 就够**：上面这些帧里 `seg` 可以换成 `wait_key`（引擎在
`ai_request`/`human_wait` 发给该拍的那枚令牌），hub 按 `w:<host>:<wait_key>` 拼段键
（无 source 时退化为 `w:<wait_key>`；host 段的理由见 §1.5）。
段键的构造规则只在 hub 一处——宿主不认识段，也不必自己造键去对齐（2026-09-19
用户拍板：宿主侧要薄，只当一个壳）。剧本节点轮的段由**常驻引擎**开与收；宿主只往里喂字。

> 为什么草稿不进主账：主账一行一改就是**整文件重写**，流式每秒几十个 chunk
> 进去必炸；旁账是独立小册子，重写代价恒定，段收口时整条撤走、定稿并进主账。
> 刷新/换端/重启：hub 读主账 + 读旁账合成，接得上。**页面不做打字动画**——
> 显示的就是 hub 给的草稿文本本身，所以多端天然一致（动画会变成第二个真相源）。

### 4.5.1 落幕扫除（row-del，2026-09-21）

`play_end` 行落账那一刻，hub 全场扫一遍：**「建立了段但没发言」的段行整行删除**
——人类旁路节点没插话的空段（如 `chat_human`）、问了没人答的只剩提问槽的段，
AI/人类一视同仁。判据：段槽里没有任何角色产出（cot/台词/工具/重试反馈…），
只剩头部槽（showprompt/prompt/name）或整段为空。有产出的段是历史，一律保留。

- journal 里被删行原位留**墓碑** `{"n","del":true,"src_seq"}`：行没了幂等键还在
  （冷加载拦晚到的重放开段帧，空段不诈尸；墓碑不计行数）；
- 广播 `{"ctrl":"row-del","n","seg"}` 给看得到该行的订阅者（REST 轮询端下次
  快照自然不见；页面按 n 摘除，没见过的 n 静默忽略）；
- 行号不回收，落幕后的新行照常续排。

## 5.3 端上输入席规范【2026-09-24 新增·UI 席位契约】

> 本节是**抽象规范**（哪些视角可以亮输入席、按钮是什么语义），不是画法——
> 输入框/按钮怎么画、放哪、什么样式，是各端个性化内容，规范不管。
> 实现参考：投影中心页 `composerAllowed()`（本规范目前唯一代码实现；
> DSH 的输入席位长在自家坐标系——主会话 composer 窗型×剧本态接管+上帝窗
> 插话分支——语义同源，实现不同）。

**hub 事实面（wire，本协议管）**：`waiting`（§6.2 `ctrl:waiting` 帧 + 快照/REST
捎带）= **席位清单**（2026-10-02 复数化：par 并发多条线各自等到人类时全部在册，
序=human_wait 到达序），每席
`{job_id, wait_key, node, actor, scope, prompt, host, out_vars[], views[], seg}`，
空表 `[]` = 没有人在等（旧形态单个对象/`null` 仅为老 hub 兼容）。`views` = hub 按
等待 scope 折算好的「人类席位视角 id 列表」——端**不做基形换算**，只比对当前
视角 id 是否在清单里；`seg` = 该席所在段键（含续跑世代键 `:gN`，hub 修正后重推）。

**可见性规范（抽象规则，各端照抄）**：

| 视角类别 | 等待期（waiting 非空） | 无等待 |
|---|---|---|
| 上帝视角 `god` / `god:<host>` | 亮（导演席） | 端自定（dsh=戏外插话常驻；页面=熄） |
| 戏内窗 `stage` | 亮（现场席） | 熄 |
| 人类席位视角（id ∈ 某席 `views`） | 亮（本人交卷席） | 熄 |
| 其他 AI 角色视角 | **永不亮** | 永不亮 |

**按钮语义（抽象规则）**：

- 发送钮 = 交卷：busy 防双投**每席一把**（该席寄出未收账期间禁用；席位离场/
  新一轮即作废）；提交走 §5.2（或 WS `ctrl:human-input`），带 wait_key 对号，
  回执也按 wait_key 落回原席。
- 变量赋值钮（可选实现）：仅 `waiting.out_vars` 非空时亮；提交 = SET VARIABLE
  行拼词 + 结构化 `variables` 随信（09-24 页面同款逻辑）。
- 上帝视角非等待期的输入语义 = **戏外插话**（`user_interjection` 信），与交卷
  是两回事——端上是否常驻输入框自定。

**端上自由（规范不管）**：输入框与按钮的绘制/样式/位置（底部、内联、就地替换
等待段均可）、markdown 渲染、草稿保持、主题、是否做变量赋值钮。

## 5.5 会话账本与 session 寻址【2026-09-20 新增·上帝窗绑主会话】

两种账本并存：job 账本（`projection/<job_id>/`，舞台窗/角色窗的读法）与会话账本
（`projection/sessions/<host>/<sid>/`，**上帝窗的唯一读法**——一个会话一生一本，
n 由会话账本自分配）。动机：原上帝窗本质是「这场戏的窗」，无戏 running 时
用户↔主 Agent 的对话不进任何账本；改造后录制无条件。

**双寻址上行**（§5 的 `/feed`，`job_id` 与 `session` 二选一，都带=400）：

```json
{"session": "dsh:session-abc", "source": "dsh", "frames": [
  {"op":"row", "zone":"outside", "kind":"whisper", "actor":"用户",
   "text":"…", "src_seq":"main:session-abc:12"},
  {"op":"seg-open", "seg":"h:session-abc:12", "zone":"outside", "actor":"导演", "role":"main"}]}
```

`session` = `"<host>:<sid>"`（两段各过 `_norm_host` 归一，拒 `.`/`..`/路径分隔符；
host 缺省可空=老宿主全局格）。会话路径**无信任集过滤、不动「最新场」指针**；
其余帧分诊与 job 路径同一套。响应带 `session` 字段。

**行路由（job 寻址帧在 hub 的 zone 收口）**：inplay/meta → job 账本（照旧）+
**织入**开戏会话的账本（副本带 `job_id` 出处标，段行同样带）；outside → owner
（信任集 host_ref）已登记时**改道**只进会话账本，未登记回落 job 账本（防丢）。
织入归属**跟戏走**（host_ref），与绑定无关；幂等靠各账本自己的 src_seq/段键查重。
job 账本的信任集过滤器对新写入就此退役（保留读旧账）。

**读法**：`GET /view?session=<host>:<sid>&view=&after=` →
`{proto, session, view, rows, next, hosts}`（'default'=最近活动会话；同三道闸：
视角过滤+显示策略+草稿合成，无信任集过滤；织入行保持 zone=inplay，stage/actor
视角在会话账本上同样成立）。

**god:<host> 视角（2026-09-21；2026-10-03 清单规则单源化）**：上帝窗带宿主来源
——`/views` 把 god 拆成 `{'id':'god:<host>', 'name':'上帝视角', 'host':<host>}`。
**清单只出「与本场有关的宿主」的 god 条目**——规则单源在 hub `view_plan(job)`：
本场相关宿主 = owners 班底（开演登记）∪ 本场行上登场过的宿主，god 清单 = 相关
宿主 ∩ god_window 申报；一家都没申报/无相关宿主 → 退化回裸 `god`（读本场 job
账本）。换 job 清单即换（跟最新时=最新场的班底）。裸 god 升级目标=「最新场」
plan 的班底第一家（2026-09-22 的「最近活动账本宿主」启发式随之退役；显式钉
job= 恒读 job 账本）。WS ctrl:view 切视角先推 {"ctrl":"view-echo","view":<规范视角id>} 再推快照（页面据此校正视角 id）。读路径 `GET /view?view=god:<host>` 与
WS `?view=god:<host>` 订阅均解析到**该宿主当前绑定的会话账本**（未绑定回落该
宿主最近活动会话；没有则空会话快照 `session:null`；会话账本空另有 job 账本兜
底，见快照节），换绑后 ctrl:view 重取即
跟随；WS 会话订阅收实时行与 row-update（绑定重解析在每次快照时进行）。

**god_window 能力申报（2026-09-28）**：上帝窗是宿主申报的能力，不是 hub 推导
的必然——宿主在能力清单 `<host>.manifest.json` 里写 `"god_window": false`，经
直连客户端登记（POST /hub-register 的 kind:host 一并捎带）报到 hub。申报了
false 的宿主：`/views` 清单**不出**它的 `god:<host>` 条目；裸 god 升级与换绑
后的视角跟随都**绝不落**到它头上（跟随目标同样读 view_plan 的 god_hosts——
本场班底 ∩ 申报；没得跟就不跟，内容由「会话账本空 → 读
那场 job 账本」兜底接住）。不申报=有（老宿主零回归）；申报是显示面的——该宿主
的会话账本照常记账织入，显式深链 `view=god:<host>` 仍可读。投影页默认看什么
由各宿主嵌页时自带 `?view=` 播种（如 web 侧栏播种 `view=stage` 默认戏内席）。

**绑定与榜单**：`GET /sessions` →
`{sessions:[{session, rows, first_t, last_t, hosts}...], bindings, latest}`
（轻量盘点绝不物化账本，按最近活动降序）；`POST /bind {"session":"host:sid"}`
显式换绑。`bindings.json`（数据根下）形状
`{"<host>": {"current": "<sid>", "mains": ["<sid>"…]}}`——录制从不依赖绑定，
绑定只是展示层「看哪本」的指针；开戏（set_owner）与会话直投首见自动收录 mains，
current 只由显式 /bind 或「首见即主」补位。`/diag` 带 `bindings` /
`session_books_loaded` / `latest_session`。

### 5.6 FEMO 会话名册与主会话面板【2026-09-21 新增】

「哪些会话算 FEMO 会话」是**宿主方言**（dsh=选了 femo 预设的会话；zcode 以后
自定义），hub 只当记账员。与绑定分家：**名册=名单**（宿主说了算），
**bindings=「主 session 是谁」的展示指针**（面板选中/宿主说话即绑说了算）。

**上行 `POST /sessions/announce`**：

```json
{"source": "dsh", "upsert": [{"sid": "session-abc", "name": "主演彩排", "job": 1948}],
 "delist": ["session-xyz"], "bind": "session-abc",
 "order": ["session-abc", "session-def"]}
```

- `source` 必填（host 名，同 /feed 纪律）；缺=400。
- `upsert` 幂等：同 id 同名同 job 跳过、改名/换 job 更新、重报即重新激活
  （active=true）。`job`=该会话最新场次（宿主 host-history 账的
  currentJobId，jobIds 兜底）——页面「选中主会话即挂上那场戏」顺藤摸的瓜，
  宿主不报则缺省（页面不切场次）。
- `order`=宿主 UI 的会话顺序全列表（**宿主界面咋排咱就咋排**：dsh 按列表页
  同款 updatedAt=max(createdAt,lastPromptAt) 降序；别的宿主按各自 UI 的排法
  ——创建时间/最后修改均可）。hub 只存不判；order 外的 sid 垫尾、不在册的
  sid 滤掉。落盘 roster.json 的 `order` 段。
- `delist` 只标 `active:false` 不删档（切走预设降级；dsh 没法切走预设不上报，
  语义留给 zcode）。
- `bind` 非空 = 宿主「说话即绑」一并换绑主 session（dsh 纪律：用户在 FEMO
  会话发言 → upsert+bind 同拍公告；upsert 先行，新会话当拍就在册再上台）。
- **只有增量、没有快照覆盖**——宿主重启后内存空了也绝不冲掉 hub 名册。
  响应 `{ok, host, bound, active}`。

落盘 `roster.json`（数据根下）形状
`{"<host>": {"<sid>": {"name": "", "since_t": …, "active": true}}}`，重启回血。

**下行与面板**：`GET /sessions` 增 `roster`/`hosts` 字段（additive）；WS 新增
`{"ctrl":"sessions"}`（拉清单）与 `{"ctrl":"bind","session":"host:sid"}`
（换绑，回执 `ctrl:'bind-result'`）；announce/bind 落账后 hub 向**全部**订阅者
广播 `ctrl:'sessions'`（载荷含 hosts/roster/bindings/sessions/latest），并对
`god:<host>` 订阅者推重解析后的新快照——面板里一点，上帝窗立刻跟过去。
网页主会话面板（projection_center.html console 栏「主会话」开关）每接入宿主
一行 = host 名 + 该宿主 FEMO 会话下拉，显示名取宿主上报的 `name`
（dsh=会话标题投影），无名显示 sid。

**dsh 侧上报方**：hostAdapter/dshAdapter/session-roster.ts——①冷扫描
（sessionQuery.listSessions 枚举主会话 × agentPreset 投影零 I/O 冷读）；
②说话即绑；③选预设入册。zcode 接入时实现自己的 announcer 即可，hub/页面零改动。

### 5.7 会话↔角色绑定（cast 选角账）【2026-09-25 新增；提名制 2026-09-26 改判】

「这场戏这个角色由哪个会话演」的账本正身，两半场：

- **提名账** `cast-preferences.json`（数据根下，落盘形状
  `{"seq": N, "hosts": {"<host>": {"<sid>": {"soul": "…", "seq": M}}}}`）——
  跨 Job 的提名：用户在 FEMO 会话（dsh=header 绑定按钮；zcode=femo_possess）
  认领角色。seq=提名序号（账内单一计数器，每次提名单调递增），定格选举
  的唯一消费方；旧格式条目无 seq 记 0。
- **选角账** `cast/<jobId>.json`——`{"jobId": N, "cast": {"<soul>":
  {"sid": "…", "host": "…"}}}`，每 Job 一份。开演定格（提名账按 seq 选举
  誊写：同一 soul 多会话提名取 seq 最大者=最后一次指派算数；只补空位不
  覆写，续跑重入不改在跑的戏）+ 运行中实际派工登记（幂等覆盖，账面随时
  反映真实现状：main 记 owner、绑定角色记被绑会话、其余记子代理会话 id）。

**消费方**：宿主派工分流（dsh 收件口查账——绑定角色由会话本尊出演、
不拉子代理；按 (job, soul) 查选角账，永不读提名账）、投影中心名册面板
「（演:soul）」标注（sid↔sid 直接配对）。
**提名制（2026-09-26 改判，废 09-25「唯一占用」）**：偏好是票不是锁——
多个会话可同时提名同一个 soul；一个会话一格，提新角色直接顶替（免先
解绑）；当选=seq 最大者，自下一次开演定格起生效，演出中冻结，戏散了
无锁残留。多票不产生投递歧义：投递按场寻址。human 角色不参与绑定
（宿主侧挡）。注意与 hub 内部「剧本演员花名册」（flow_start 的 _cast）
是两回事：那个记「戏里有哪些角色」，这本记「角色由哪个会话演」。

**API 四路**：

- `POST /sessions/cast-preference` `{"host","sid","soul"}`（退票 soul 传
  `null`）→ `{ok}` 或 `{ok:false, error}`（仅缺参拒绝，无占用冲突）。裁决在 hub。
- `GET /sessions/cast-preferences` → `{ok, bindings: {soul: {sid, host}},
  hosts: 原始分格}`——bindings=各 soul 的当选提名（seq 最大者，即下一场
  定格将选出的人）；网页标注与宿主钩子查询共用一份视图（会话→角色查
  `hosts`，角色→会话查 `bindings`）。
- `POST /cast` `{"job_id","soul","sid","host"}`=登记一条（幂等覆盖）；
  `{"job_id","subkind":"snapshot"}`=开演定格（宿主在 job_start/续跑成功后
  调一次，返回 `{ok, count}`，count=本次新补条数）。
- `GET /cast?job=N` → `{ok, jobId, cast}`；无档=空账（选角是渐进账，
  缺页=还没登记；不设「最新场」缺省语义，消费方明确知道在看哪场）。

**宿主侧读写口**：femo2host/host/cast-core.mjs 五口（读/登记/定格/绑解/
视图），hub 地址走 hub-client 唯一解析口。新宿主接入=消费同一本账+同一
个客户端，绑定入口形态自便（按钮/工具/chip）。

  `{"ctrl":"human-input-result","code":200,"ok":true,"letter_id"}`，语义同 §5.2）。
  **快照与订阅入册同锁**：不漏行；断线重连带 `after=next` 续传。
- **GET /view?job=&view=&after=** → `{proto, job, view, rows, next, hosts}`
  （`hosts` = 该场出现过的来源名，按出现序）
- **GET /views?job=** → `{job, hosts, views:[{id, name, key, base, host}]}`。
  **id 稳定键**：单来源 `'actor:' + 基形`，带来源 `'actor:<host>:<基形>'`
  （§1.5）；name = 显示名（会变长，**永远是裸名**）；base = 裸基形；host = 来源；
  key = sanitize(键)。
- **GET /jobs** → `{jobs:[{job_id, rows, first_t, last_t, hosts}], hosts, latest}`
- **GET /chronica** → `{chronica:[{session, jobs, first_t, last_t, rows}]}`
  （台账场次清单，2026-09-29 新增：按引擎台账场次号归拢 job——号取自各 job
  账首行 play_start/play_resume 的 `femo_session_id` 字段（§1）；jobs 升序=

  `{"ctrl":"chronica"}` → `{"ctrl":"chronica","chronica":[...]}`；整场视角
  id=`chronica:<台账号>`，在 /views 的清单里以「整场回放」条目出现）
- **GET /hosts** → `{hosts:[{name, last_t}]}`（本 hub 见过的宿主名册）
- **GET /live?job=** · **GET /replay?job=**（NDJSON）·
  **GET /health**（带 `hosts`、`waiting`）· **GET /diag**（subs/ws/live_blocks/
  books_loaded/**hosts**/**owners**——`owners` = 最新场 `host → [sid]` 信任账，
  联机排障用）

### 6.2 人类等待态（ctrl:waiting）【2026-09-20 新增；2026-10-02 复数化】

引擎 `human_wait` 按席 SET（键=wait_key）/ `human_done` 按事件带的 wait_key
清那一席（引擎 2026-10-02 起 human_done 带 wait_key——par 同名并发节点下节点
名不可辨；老引擎不带键=全清）、`flow_done/error/paused` 全清（暂停即收麦；
续跑重进节点会重发全新 wait_key，输入框自动回来）。**控制态不是行**：不过
VIEW_POLICY、不落账本，全订阅者无差别广播。**席位清单**（数组，序=human_wait
到达序；par 并发多条线各自等到人类时全部在册）：

```json
{"ctrl":"waiting","waiting":[
 {"job_id":1932,"wait_key":"j1932:human_[陈述]_3",
  "node":"[陈述]","actor":"@猫猫","scope":["@猫猫","@Eve"],"prompt":"请发言",
  "host":"dsh","seg":"w:dsh:j1932:human_[陈述]_3",
  "views":["actor:dsh:@猫猫","actor:dsh:@Eve"]}]}
```

清空 = `"waiting":[]`（老形态单对象/`null` 仅为旧 hub 兼容，端上应归一成清单）。
`views` = 该亮输入框的 **actor 视角 id 清单**（与
/views 的 id 逐字同口径，含 host 前缀）；god / stage 两视角页面自判永远可亮，
AI 角色视角不在清单里天然不亮。`seg` = 该席所在段键（含续跑世代键 `:gN`——
hub 在段落地那一拍修正后原位重推）。输入框可见性=页面拿当前视角 id 逐席现算，
hub 不做视角过滤。交卷回执（`ctrl:human-input-result` 与 REST 同款）带
`wait_key`：多席并发时端上按它把受理/失败落回原席。竞态兜底：镜像滞后时交出
的旧信由引擎 `deliver_human_input` 活跃+归属校验拒收（死信，不上墙）。

## 7. 身份与隔离（第三方必读）

- **job_id 归引擎**：它是续演/resume 的锚，hub 不发号、宿主不许发明。
- **租户边界 = FEMO_DATA_DIR**：每个宿主部署显式设自己的 `FEMO_DATA_DIR`
  （与 mailbox 同纪律），账本落在 `<FEMO_DATA_DIR>/femo/projection/<job_id>/`。
  共享同一数据目录的两个部署 = 同一个租户，job_id 天然不撞。
- **hub.json 自发现** `{host, port, pid, started}`：hub 干净停机即删；
  读到但连不上就当过期件处理。
- **安全面**：只绑 127.0.0.1、无鉴权——账本落盘文件本机任何进程本就读得到，
  HTTP 鉴权不改变威胁模型；别把 hub 端口暴露到环回之外。

## 8. 处理次序与保证

- 同一 feed 批内逐帧按序处理；行号 = 到达序 = 权威序。
- 快照与订阅入册、落账与广播，各自在同一把锁的临界区内——不丢行、不重排。
- `src_seq` 按 Job 去重：重放、冷唤醒都安全。
- 直播帧（live-*）永不落盘；转正只有 live-done 一条路（drop/sweep 清块不转正）。
- 草稿帧（draft-*）也不进主账，只进旁账；快照 = 主账 + 旁账合成，
  所以刷新/换端/重启接得上。段收口后草稿一条不剩（吸收或转正）。
