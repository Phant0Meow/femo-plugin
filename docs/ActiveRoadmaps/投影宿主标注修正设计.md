# 投影行宿主标注修正：以 mailbox 投递事实为准（2026-09-25 定稿；2026-09-26 已随引擎常驻化刀1 实施）

## 一、问题（job 2564 双宿主演出实证）

dsh 发起的演出里，zcode 附身的 Eve 与 dsh 绑定的小猫咪同台。投影 journal
里**所有行/段全部标 `dsh-3081`**，Eve 段也不例外。用户期待：Eve 属于
zcode，就该注明 zcode。

根因：EventProjector 的 host 是**进程级单一值**（`set_host`=本桥自称），
段键 `w:<host>:<wait_key>` 与视角 id 全盖这一个章。喂行方（发起方桥）=
dsh-3081，于是演员归属 zcode 的段也盖 dsh-3081。单宿主时代喂行方恒等于
演员归属方，问题不显；跨宿主派工打通（695d897）后暴露。

注：段键宿主前缀防「令牌撞号」的旧说法，作者已确认非其拍板（AI 总结时
的归属夸大）；前缀本身保留（多宿主确需防撞），但**取值来源**改为演员
归属宿主。

## 二、信息源裁决（作者拍板）

**mailbox 投递事实 > 选角账登记声明**。选角账说「应该归谁」（意图，可能
登记错/热改/键 miss）；mailbox 信落在哪个格是**实际发生的投递行为**
（事实）。信不删除、每封自带 `target_host`——投递事实完整可查。
（与 main-actor「账本可能失真、事实源不会」双证据纪律同一哲学。）

## 三、设计

1. **投递事实记录**：桥 ai_request 产信分支（现 foreign_pickup 判定处）
   产信后记 `dispatch_facts[(job_id, soul)] = target_host`（桥内存 dict；
   本宿主直推的也记 args.host，统一事实）。
2. **事实注入投影**：EventProjector 加 `set_dispatch_lookup(fn)`，fn
   `(job_id, soul) -> host or None`（桥闭包查 dispatch_facts；无事实返回
   None）。产信现场与投影同刻同进程，跨重启丢事实=回落本桥自称（重启
   本有 play_paused/resume 行分隔，段本断，可接受；二期可回落选角账）。
3. **段键取值**：`_seg_ref` 增加 host 参数，调用点（on_event 的段开/收、
   on_post_speech）以事件里的 soul（顶层 actor_info.soul 优先——与桥
   to 解析同源，resume 缺口已修）查事实得 host；查无回落 self.host。
4. **视图 id**：跟随段键自然带归属宿主（`actor:zcode:@Eve`）。dsh client
   的视角菜单/窗 id 解析（parseProjectionWindowId）需兼容多 host 形态——
   实施时核对 client 解析面与 `actor:zcode:@Eve` 与既有
   `actor:<基名>`（单宿主无前缀）两形态。
5. **行本体不加 host 字段**（行归段、段带归属）——与「前端忠实反映
   hub 数据」不冲突：段键即事实。

## 四、风险与边界

- 段键变化=接缝变化：逐字流 draft 键须同源核对（job 1927 孪生段教训）。
  跨宿主角色的逐字流本不经过发起方 client（zcode 侧逐字流为独立缺口），
  实际撞键面小，实施时逐调用点核对。
- resume 跨重启：事实丢失回落喂行方，同角色段键可能跨重启漂移——段以
  play_resume 行分隔，接受。
- ~~投影中心网页零改动~~（**勘误 2026-09-26，实施时实测改「读者改一行」**）：行
  本体退役 host 字段后，读行 host 的读者要跟着改——投影页行头徽标一行
  （拆分后在 projectionCenter/render.mjs，hostTag(r.host || HRC.segHostOf(r.seg))）；
  hub-render-core.mjs 经 grep 核对**无**行 host 消费面，不需改。旧账本行自带
  host 字段，读端 `r.host || 剖段键` 双态兼容。

## 五、验收

双宿主真演出一场：journal 段键 Eve=`w:zcode:…`、小猫咪=`w:dsh-3081:…`；
投影中心视角下拉/段标注各归各家；逐字流/草稿无孪生段；单宿主演出回归
零变化。
