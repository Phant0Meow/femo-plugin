# 宿主接入清单——不管哪家 Host，都要实现哪些接口

> 这份文件回答一个问题：**接入一个新的宿主（或盘点老宿主），到底要写哪些东西？**
> 它是清单不是守则——架构裁决与红线见 AGENTS.md（根 + hostAdapter），两边冲突以 AGENTS 为准。
> 判断每条接口归谁的口诀：设想明天换一个完全不同的 harness——**femo 系统不用变的，都不归你写；必须重写的，才是宿主的事**。
>
> **读法**：每节分两段。第一段「这一块是干嘛的」纯人话，零术语零代码，讲明白这件事在剧场里为什么非有不可；第二段「怎么接」才是干货，出现具体公共件、参照实现与契约细节。只想知道大局的读第一段就够了，动手的人读第二段。

## 〇、一张图：宿主在剧场里的位置

引擎（femoCompiler）埋头演戏，住在**常驻引擎** `femo_daemon.py`（femo2host/python/）里——每数据根一座、脱离一切窗口、闲时不散场，死了被任何客户端惰性代拉；驿站管迟到的人；投影中心（hub）与引擎同进程（HTTP 面挂在 8790 上的同一个服务）。**宿主 = 让这场戏在自家环境里发生的那个人**：连上常驻引擎、把 AI 的手（工具）接上、把信送到该收信的会话、记住戏演到哪了、把看见的东西画出来。

好消息：公共层（femo2host/host/）已经把这些事的「决定做什么」收编得差不多了——**宿主的基本功是消费公共件，不是重写逻辑**。下面按必做程度分六组。

---

## 一、接引擎：连上常驻进程

**这一块是干嘛的**：引擎有自己的常驻进程（hub+引擎同进程，发现账=`<数据根>/projection/hub.json`），你不需要拉起任何 Python 子进程。宿主第一件事是**连上它**：发现它、死了顺手代拉它、保证随时能喊应答——喊得应，戏就能开；它半路换家（代拉重生），你得跟着搬并把手头的事清一清。另外你要给自己起一个名字——整个剧场（包括别的宿主）都靠这个名字认出「这条消息是谁家的」。

**怎么接**：

| 要做的事 | 公共件（直接消费） | 说明 |
|---|---|---|
| 宿主能力清单 | — | 写一份 `<host>.manifest.json`（host 字段=宿主自称，**这个单词是全局身份**：喂 hub 的 source、选角账、名册都用它），路径交直连客户端（job_start/job_resume 时随场注入引擎）。清单同时是**宿主能力申报面**（2026-09-28）：直连客户端登记（/hub-register）时把清单里声明的能力一并带给投影中心，现行一项=`god_window`（布尔，本宿主有没有上帝视角窗，见《投影中心行协议》§6；**缺省=true**，投影页默认看什么的另一面由各宿主嵌投影页时自带 `?view=` 播种，如 web 侧栏播种 `view=stage`） |
| 连接与看门 | `daemon-client.mjs` | 直连客户端唯一一份：发现账探活双验（hub.json 指纹+引擎面，旧版响亮拒绝）→ 死/无则**脱离母进程代拉** femo_daemon → 命令 POST `/cmd/<cmd>`（自动注入 `_caller_host` 与 `_host_manifest`）→ SSE `/engine/events?host=<宿主>` 直播（live-only+归属闸）→ 推送户再给 `pushUrl` 开门铃心跳。接口与旧电话机同形（start/send/stop/alive/onEvent/onExited），写一个薄绑定壳注入本宿主身份即可（参照 zcode `engine-bind.mjs` / dsh `bridge.ts`）。**stop 只断自己不发 shutdown**——引擎常驻站岗，关窗戏演完。登记时自动从清单读 `god_window` 一并上报（`_manifestCaps`），宿主侧零额外接线 |
| 引擎生死 | onExited → 清账 → 重连 | SSE 断流/命令失联时客户端自动重发现+代拉；hub.json 的 **pid 换人才**向宿主报 onExited——宿主据此清在飞演员与镜像（dsh 的 `bridge-supervisor.ts` 是参照实现：清账+ping 轮询+重建索引+30 秒三连崩熔断），重连由客户端自愈 |
| 身份双词 | — | 宿主自称（manifest host 字段）+ 信箱宿主 id（多实例部署时按端口等派生，如 dsh-<port>；客户端 `host` 参数，归属闸/门铃/host_refs 键同一词）。只用于「谁写的」，不用于「谁的地盘」 |

> 历史注记：2026-09-26 前宿主各自 spawn 一个桥子进程（`bridge-launch.mjs` 三件套 + `bridge-client.mjs` 电话机 + `femo_bridge.py`），常驻化第 3 步后三家主力宿主全部直连，这套生桥机器仅余 autoclaw（待其适配器重改后切直连）与回滚路径引用——**新宿主一律走 daemon-client 直连，勿再复活生桥链**。

## 二、工具面：把 AI 的手接上

**这一块是干嘛的**：戏里的导演（主模型）要能干几件具体的事——把剧本装上台、喊开演、中场叫停、续演、查角色库、翻演出记录、带妆彩排。这些「手」的定义是全剧场统一的，你不能自己发明一套动作叫法。除了手，还得给他一本「操作手册」：戏怎么演、台词规矩是什么——这本手册全世界只有一份正本，你负责把它翻译成自家模型能读到的方式。

**怎么接**：

| 要做的事 | 公共件 | 说明 |
|---|---|---|
| 注册总纲工具 | `tools-core.mjs` | `buildToolSpecs({host, possess})` 出规格（名字/描述/参数，描述按宿主措辞，参数名全局统一）；非会话型宿主直接用 `createBridgeToolImpls` 全套执行体（挂载/开演/暂停/续跑/角色库/台账/干跑），会话型宿主（如 dsh）照 `tools.ts` 形态注入自己的执行体，但规格与归一口径仍取总纲 |
| 注入宿主依赖 | — | 工具执行体要注入：`ensureBridge`（没起则连上等就绪）/`send`（引擎命令，=直连客户端 send）/`femoRoot`/`host`/`hostRef`/`spawnPython`（台账 CLI 一次性子进程，env 补 UTF-8）/`debugSpawnProc`（干跑监工适配器，契约见 debug-run-core 文件头）；要附身工具就再注入 possess 三件（本会话身份/演出态/名册联动），`possess:true` 规格里才附上 femo_possess |
| 教条链（SKILL） | `femoGenConnector/SKILL.common.md` | 教条正本唯一份：宿主用自己的加载器按 INCLUDE 指令展开它，`{HOST}` 占位符由加载器统一替换；宿主特有内容（开场白/视角窗口/喂拍方式）写进**自家附录**，正文勿动。两条硬规矩：系统提示词只在「FEMO模式」的 preset 里注入，其他模式不注入；**不写死绝对路径**，一律 `{FEMO_ROOT}` 占位符 |

## 三、驿站：把信送到该收信的会话

**这一块是干嘛的**：戏演起来后，每拍戏都要找到该接它的人——轮到导演了，剧本和场上情况要送到导演面前；轮到某个演员了，料包要送到那个演员手里；轮到观众（人类角色）了，要有人递话筒；戏停了或出了岔子，总结要送到导演桌上。这些「信」都先进一个公共的信柜，宿主负责最后一程：**从柜子里取出信，送到自家人手里，再把回话交回柜子里寄出去**。

**怎么接**：

信封、驿站、两阶段回信的纪律全宿主同一套（八维信封、target_host 必填、ref=wait_key 凭据对号入座、滞留件等急件一起走），公共件已收口：

| 拍 | 信从哪来 | 宿主要做的 |
|---|---|---|
| 主演轮（source:main / 被附身会话） | 常驻引擎产信进驿站（kind=context 急件） | 到站取信（自取或投递员，消费 `mailbox-push-core.mjs` 分拣）→ 注入主会话 → 回信经驿站寄出，**交卷信封唯一出处 `speech-core.mjs`**（executorSpeechArgs：先应答收讫、台词写 payload） |
| AI 演员轮 | 同上（soul=角色） | 派工分流：**已被附身/绑定的角色由其会话本尊出演**（不拉子代理）；未绑定的拉子代理（常驻会话或导演邮差，各家形态自定）。**停靠重试**：审稿失败引擎发 node_retry 信，接 `node-retry.mjs` 停靠租约（信面单交 `broker.deliverRetry`，租约零宿主依赖白得；zcode 至今缺这块是记录在案的能力缺口，新宿主别漏） |
| 人类轮 | 同上（soul=人类角色） | 提供输入席（网页就地输入/终端席/主会话均可），交卷走 `speech-core.mjs` 的 humanSpeechArgs 人类信封 |
| 用户插话（演出中用户跟导演说话） | 常驻引擎产信（subkind=user_interjection 急件） | 送到主会话对话流，**必须保住 source=user 标记**（前端据此画用户气泡而非系统注入）；投递失败即死信，宿主降级直推 |
| 终局/警告 | 常驻引擎产信（notice 急件/滞留件） | 送到导演面前；终局措辞唯一出处 `notice-core.mjs` formatStopNotice，宿主不手拼；滞留件等急件一起走 |

**选一个送达模型**：**推**（宿主常驻收件口，投递员上门——设 FEMO_PUSH_PORT 起监听器，POST 载荷与 `mailbox-push-core.mjs` 的分拣协议同形；dsh 的 mailbox-push、autoclaw 的收件口是参照）或 **拉**（客户到站自取——zcode 的钩子到网关取信）。混用也行，但一条拍只走一条路。**注意一个选型后果**：开演通知这类急件**只给挂了收件口的宿主产信**——选「拉」的宿主拿不到这类信，要靠自家轮询兜底，别当成信丢了。

## 四、黑板：记住现在演到哪了

**这一块是干嘛的**：剧场里随时有人问「现在什么情况」——用户想按暂停键，得先知道有没有戏在演、是哪一场；想给某个会话换角，得先确认它没在演出中；画布刷新了，得知道该恢复成什么样子。这些问题不能每次都去后台翻档案（太慢），所以宿主手里要有一块**小黑板**，上面用粉笔写着当前的场次、状态、等谁输入。粉笔字允许和档案偶尔对不上（对上了有专门的收口机制），但黑板必须有人写。

**怎么接**：

| 要做的事 | 公共件 | 说明 |
|---|---|---|
| 持有镜像实例 | `run-state-core.mjs`（状态机唯一份） | 宿主建一份 RunState（jobs/sidIndex/sessionActors/errors），状态机的纯函数全在公共件：`jobMirrorPrearm`（开演命令回执即写=最早证据）/`jobMirrorCorrect`（flow_start 校正）/`jobMirrorSetState`（返回 changed 供广播判定）/`clearActiveIfActive`/`isSessionRunning`/`activeJobOf`/`projectionStateOf` |
| 三个写入时机 | — | 镜像三收敛源：①开演/续跑命令成功回执（prearm）②引擎事件到达（correct/setState 校正）③进程死亡（清账）。状态权威在引擎 runs/<job_id>.json 档案，宿主黑板只是秒答抄本 |
| 广播插座 | — | setState 返回 changed 时宿主自己广播快照（黑板变了要喊一嗓子，各家通道自定——dsh 是 SSE run_state/projection_state） |
| 消费面 | — | 演出冻结判定（选角 409）、暂停按钮的目标解析、门卫放行（isMainAnswerPending/isSessionRunning）、投影窗按钮状态（projectionStateOf）、人类等待快照（waitingHumanFromEvent）全从黑板读 |

## 五、幕布：把看见的画出来

**这一块是干嘛的**：戏演了，总得有人看得见。后台已经有人自动把戏里发生的事一句句记到公共的账本上（这件事你一行代码都不用写），你要做的是两件小事：一，自家环境里用户和导演的日常闲聊，也照规矩记到账本上（不然回看时只有戏没有闲聊）；二，给用户一个「看戏的窗口」——可以直接用现成的投影中心网页，也可以自建。另外，开会前要在观众名册上登记你家有哪个厅，别人才能找得到你。

**怎么接**：

| 要做的事 | 公共件 | 说明 |
|---|---|---|
| 戏内行 | **零工作量** | 常驻引擎的 EventProjector 在引擎事件现场自动喂 hub，行自带宿主 source |
| 戏外行 | `hub-feed-core.mjs`（喂送协议机唯一份） | 用户与导演的闲聊：宿主捕获（何时录、录谁，各家自定闸门——**认不出 FEMO 会话就只在演出中录**，防普通聊天混进历届主会话；FEMO 身份只增不减、阴性不缓存）按 §5.5 会话寻址直投。上行学问全在公共件：微批 40ms/20 条、best-effort 绝不挡演出、段引用两字段语义互斥（ref=引擎令牌发 wait_key / segRef=宿主自造整键发 seg，混用=字落幻影段页面不长字）、src_seq 幂等 |
| hub 地址 | `hub-client.mjs`（唯一解析口） | **必须读自发现文件 hub.json**——桥端口被占时会向上漂移，硬编码 8790 会把行静默喂进隔壁 hub（喂错不报错，实测坑） |
| 投影窗 UI | 投影中心网页由 hub 直接伺候（零工作量） | 自建窗可选（dsh 的会话窗+锚行、zcode 的画布监视器）；画读侧一律 hub `GET /view`，宿主不存投影历史；自建网页的行解释/输入席可见性等抽象规范用 `hub-render-core.mjs` |
| 逐字直播（体验项，可后置） | `hub-feed-core.mjs` | 打字机效果=宿主把自家模型的流式增量按段引用喂 hub（引擎拍的字 ref=wait_key、自家轮的字 segRef=自造整键）。不喂也能看（等整段落账），喂了才有过打字机的体验 |
| 名册接入 | — | 开演 `POST /sessions/announce`（upsert+bind）——投影中心网页的主会话面板由此认得你 |
| 选角（可选） | `cast-core.mjs` | 绑定入口随宿主（dsh=会话界面、zcode=MCP 工具 femo_possess）；提名账正身住 hub（cast-core 走 /sessions/cast-preference，提名制——多会话可同提一个 soul，当选=最后指派、开演定格生效）；派工分流读每场选角账（(job, soul) 寻址，不读提名账） |

## 六、必做：卫生与验收

- **沙盒三通道**：跑测试必设 FEMO_DATA_DIR，引擎 DB/驿站/投影账本三条通道全部进沙盒——漏任何一条，测试的信会被钩子当真通知注进会话。
- **冒烟**：各自适配器目录下锚持久沙盒；冒烟至少覆盖「挂载→开演→领拍→回信→终局」一条全链。
- **上线实证**：重启后查进程表（femo_daemon.py 的命令行路径是硬证据）；真实演出目检上帝窗是金标准——单测只护语义不护时序。

## 七、宿主形态自由区（公共层没有、也不该有）

这些是各家的物理形态，想怎么写怎么写：

- 进程载体：进程内插件 / MCP+hooks / Chrome 扩展+本地服务；
- 投影窗长相（自建的话）；
- 演员执行体形态（常驻子代理 / 一次性 / 网页会话）；
- 注入通道（steer / 钩子注入 / 下一轮注入）；
- 绑定入口长相（下拉菜单 / MCP 工具 / 扩展 chip）；
- 版本兼容胶水（对旧版宿主本体的双版本分流——新宿主瞄准现役构建，一般用不上）。

## 九、接入顺序建议（新宿主照这个次序走）

1. 引擎连上：manifest + daemon-client（发现/代拉/命令/SSE），ping 通即算过；
2. 工具面：总纲注册 + 教条链展开，femo_mount/femo_run 能跑通（此时戏内行已自动进 hub——开投影中心网页就能看）；
3. 主演轮：驿站取信→注入→回信，跑通 source:main 的剧本；
4. 黑板：接 run-state-core，开演/收口/死亡三个写入时机点亮（暂停/冻结/恢复面都靠它）；
5. AI 演员轮：子代理或会话本尊 + 停靠租约，跑通多角色剧本；
6. 名册+戏外行+选角：面板可见、闲聊入账、派角分流；
7. 真演出目检上帝窗——过，才算接入完成。
